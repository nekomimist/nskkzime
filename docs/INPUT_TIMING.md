# TSFキー処理と候補描画の計測

検証アプリの「遅延計測（本文なし）」で、そのアプリの入力スレッドだけを計測する。
既定はオフ。読み・本文・キーコードは収集せず、ファイルにも保存しない。
設定ファイルを変更する [入力診断ログ](DIAGNOSTICS.md) とは独立している。

## 計測範囲

| 表示 | 開始と終了 | 含まないもの |
|---|---|---|
| TSF OnKeyDown | DLLの `OnKeyDown` 入口から復帰まで。同期編集・候補更新の処理を含む | それ以前のOSキー配送、`OnTestKeyDown`、キー解放、非同期推論の応答待ち |
| 同キー開始→候補WM_PAINT終了 | 同じ `OnKeyDown` 中に更新した候補一覧が、nskkzime自身のウィンドウで描画を終えるまで | 本文欄の描画、アプリ独自の候補UI、DWMの画面提示・モニターの応答 |

`OnKeyDown` は消費しなかったキーや失敗した編集も呼び出された分を含む。
候補描画は登録／削除確認欄を除き、初回表示とキー操作による候補更新を含む。
後から届いた推論応答の描画へ、以前のキーの開始時刻を引き継がない。
生成された候補をキーで選び直す操作は対象になるので、辞書だけの測定と実モデル連携中の測定は分ける。

各系列は直近2048件だけをメモリーに保持し、累計件数と現在の標本数、p50・p95・最大を表示する。
パーセンタイルは昇順のnearest-rank方式。標本がない場合は「未計測」と表示する。
描画前に別の候補へ置換・非表示・取消になった更新は所要時間に混ぜず、「描画前の破棄」へ数える。
まだ描画されていない更新は「描画待ち」に残る。表示をホストが抑制した場合も成功した描画には数えない。
標本数に加え、これらの件数を確認する。

有効化・無効化のたびに全標本をリセットし、以前のキーや描画待ちを無効化する。
同一スレッドで再入したキー処理は、各呼び出しを別々に計測する。
オフ時は時計を読まず、標本配列も確保しない。有効化の操作時にだけ配列を確保し、
オン時の入力処理では固定長の配列へ数値を追加するだけ。
集計・表示用の文字列作成は検証アプリの約300ms間隔の更新時に行う。
計測と診断表示自体の負荷はゼロではないため、測定条件に含める。

### キー処理の内訳

診断欄を下へスクロールすると、キー処理中に呼ばれた次の操作の時間も表示する。

| 表示 | 範囲 |
|---|---|
| 受付判定 | 編集可否・モードキー・キー翻訳・SKKでの処理可否の判定 |
| 編集要求 | 同期編集セッションの作成から `RequestEditSession` の復帰まで |
| 編集コールバック | 同期セッション内の後始末、範囲照合、SKK操作と編集・候補更新 |
| 既存compositionの照合 | 変換範囲の本文と選択位置の検査 |
| 入力コア | コアの状態コピーと `Engine::handle` |
| TSF本文編集 | 変換範囲の作成・変更・終了、書き換え、属性と選択位置の反映 |
| SetText/InsertText | TSFの本文書き換え／挿入APIの呼び出し |
| 表示属性 | 下線等の属性のクリア／設定。1キーで複数回の場合がある |
| 選択位置 | 末尾の選択範囲の作成と反映 |
| 候補更新 | TSF候補通知、位置問い合わせ、独自候補ウィンドウの更新 |
| モード同期 | 通常のSKK操作後のWindows入力モードとの同期 |

内訳も各系列2048件まで。件数はキー数ではなく操作の呼出し数で、呼ばれない操作は標本を追加しない。
内側の操作・ホストへの再入・待ち時間を含むため、各系列の時間やパーセンタイルを合算してはいけない。
モードキーを受付判定で処理した場合は、その切替時間も受付判定に含む。
キー処理の外で実行された非同期応答や編集は内訳へ加えない。
オフ時は内訳の時計も読まず、配列も確保しない。オン／オフ時に全系列を一緒にリセットする。

## 実測手順

1. 標準のzenz入りReleaseをビルドし、`out/build/windows-x64-zenz/Release/ime_probe_local.exe` を起動する。
   Windowsに登録済みの版を測る場合は `ime_probe.exe` を使い、状態欄のDLLパスも記録する。
2. 辞書の読み込み完了後、通常の変換を何度か行ってウォーム状態にする。
   「文脈確認」はオフにし、入力診断ログ・推論・学習の設定を測定条件に記録する。
3. 「遅延計測（本文なし）」をオンにして、標準EDITで決めたキー列を繰り返す。
   例: `Kanji` → Space → Space → Enter。初回候補、候補移動、かな入力を分けた記録も取る。
4. 表示の件数・p50/p95/最大・描画待ち／破棄数をコピーする。DLLのSHA-256、CPU、OS、DPI、
   辞書・設定、入力欄、キー列と回数も記録する。本文を記録へ含める必要はない。
5. 一度オフにしてからオンへ戻し、RichEditで同じ測定を行う。終了またはオフで標本は消える。

「遅延計測」が操作できない場合は、読み込まれたDLLがこの診断エクスポートを持つか確認する。
古い登録版を自動で更新する仕組みではない。

## 自動検証と残る確認

`input_timing` は標本上限とパーセンタイル、既定オフ、遅延描画の対応付け、置換、
再入、計測切替中の古い処理、スレッド分離を検証する。
`candidate_ui` は候補更新からの計測開始と、ホスト側の表示抑制・位置不明時の除外を確認する。
`tsf_smoke` は実DLLのエクスポートと、テスト用TSFホスト経由のキー処理の採取を確認する。

これは計測機能の自動検証であり、実入力のp95達成を示す値ではない。
検証画面と実際の候補描画は下記の短い試行で照合した。
外部アプリ、十分な回数のウォーム状態、OS配送を含む遅延の実測は残る。
計画のキー処理5ms・辞書候補提示20msという目標は、引き続き達成と判定しない。

## 2026-10-07の実画面での初期試行

zenz入りReleaseの `ime_probe_rules.exe` をComputer Useの実キー操作で検証した。
これは計測機能の動作確認を兼ねた少数標本であり、性能評価の完了ではない。

- ソース: `d5847b1`。ロード先は `out/build/windows-x64-zenz/Release/nskkzime_tsf.dll`。
  DLL SHA-256: `8c378b5904a9bf22dafe0cdfa1ab3381f8816e7cba5a3e1a89b828734d0d5485`。
- Windows 11 x64、ビルド `10.0.26300`、AMD Ryzen 9 7950X3D。
  Windowsの `WindowMetrics/AppliedDPI` は144。モニター別の有効DPI・移動時の挙動は未計測。
- 辞書は `tests/fixtures/probe.utf8.skk`（9見出し・33候補）、
  ローマ字は `tests/fixtures/romaji.tsv`。学習・推論・入力ログ・文脈表示はオフ。
  推論停止時の辞書経路の確認であり、zenz動作中の測定ではない。
- 標準EDITは `Kana` → Space → Enterで一度変換・確定してから計測した。
  RichEditはその欄での最初の入力を含む。両者を同じウォーム条件とは扱わない。
- 各欄で `/` → `p` → Space → PageDown → PageDown → Space → PageUp → Escape → Escapeを1回実施。
  各キーの間にUIを観察し、300msの診断表示更新後に最終値を取得した。
  連打や通常速度の連続入力、観察ツールを使わない条件は未測定。

両欄とも描画待ち・描画前の破棄は0件。候補01→08→15→16→09の表示、
Escapeで読みへ戻ること、次のEscapeで読みだけが消えることを画面で確認した。
計測をオフにすると表示もオフになり、再度オンにすると全件数が0へ戻った。

この標本数ではnearest-rankのp95は最大値と一致する。
TSF内部だけでも5msを超えるキー処理があり、目標達成の根拠にはできない。
次は同一条件での反復測定と、同期TSF編集・候補更新の内訳を調べる。
候補描画がこの試行で20ms未満でも、OS配送や画面提示までの20ms達成を意味しない。

### 重複する選択位置更新の省略後

ホストが既に本文末尾へ空の選択範囲を移動している場合だけ、`SetSelection` を省くよう変更した。
範囲選択・interim selection・選択取得失敗・末尾以外では従来の反映処理を行う。
実DLLのテスト用ホストで、自動移動する場合の重複通知抑止と、自動移動しない場合のカーソル反映、
範囲選択の置換、interim／取得失敗時の通常反映を検証した。Releaseの全51テストも成功。

### 同一本文の更新省略後

表示中の候補の確定や登録欄だけの編集など、既存compositionに反映する本文が変わらない場合の
`SetText` を省いた。前回の本文との一致だけで判断せず、現在のTSF範囲とも再照合する。
照合中のホスト編集・composition終了を検出すると反映を中止する。確定処理・属性・選択位置は更新する。
`SetText/InsertText` 系列には実際にAPIを呼んだ場合だけを数える。

同日の `95d442a` にこの変更を加えたReleaseで測定した。実測時のDLL SHA-256は
`6c3d115bddf83d7bd411bbcd3988481fb2978bcb4ce8867e7ee15181d28b98d8`。

`/` → `p` → Space → PageUp → Enterを3回（15キー）入力した。
