# ローマ字ルールの設定

内蔵のローマ字ルールに、UTF-8のタブ区切りファイルで追加・上書きできる。
辞書検索とは独立しており、通常入力・変換用の読み・送り仮名・登録欄内で共通して使う。
カタカナモードでは出力のひらがなをカタカナへ変える。

## 設定する

[サンプル](../examples/romaji.tsv) を別の場所へコピーして編集し、絶対パスで登録する。

```powershell
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-romaji 'C:\設定\romaji.tsv'
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --check
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --reset-romaji
```

`--set-romaji` はファイル全体を検証してから、既存の `settings.ini` へ `romaji=絶対パス` を保存する。
辞書の優先順と学習設定を維持し、不正なルールや保存失敗では前の設定を保つ。
`--reset-romaji` は内蔵ルールへ戻す。元のルールファイルは削除しない。
`--show` は保存先と設定値、`--check` は実際の読み込み結果を表示する。

変更は利用するアプリを起動し直すと反映される。入力中のファイル監視・再読み込みはしない。
一度読み込んだルールは入力セッション中は不変で、キー処理からファイルへアクセスしない。
起動時に読み込めない場合は内蔵ルールで入力を続け、検証アプリの診断へ理由を表示する。
出力内容そのものは診断へ含めない。

保存せずにCLIで試すこともできる。

```powershell
.\out\build\windows-x64-zenz\Release\skk_trace.exe --romaji .\examples\romaji.tsv 'wi,tp.'
```

サンプルでは「ゐ，東京．」となる。GUIで試す `ime_probe_rules.exe` は専用fixtureを使い、
学習とダミー推論を無効にする。通常の保存設定は変更しない。

## ファイル形式

最初の有効行は `version=1`。続く各行は以下の2列、または3列。
列の間は実際のタブを使う。文字列 `\t` やLisp形式は解釈しない。

```text
入力<TAB>出力<TAB>次に残す入力（省略可）
```

| 入力 | 出力 | 次に残す入力 | 例 |
|---|---|---|---|
| `wi` | ゐ | なし | `wi` → ゐ、カタカナではヰ |
| `.` | ． | なし | 句点の表記を変更 |
| `tp` | 東京 | なし | 辞書を使わず略記を展開 |
| `jj` | っ | `j` | `ajja` → あっじゃ |
| `nn` | ん | なし | `hannou` → はんおう（DDSKKの既定に相当） |

3列目は出力後に未完成ローマ字として残し、次のキーで続きを処理する。
ただちに再変換しないため、循環ルールで処理が止まらなくなることはない。
Backspaceで編集でき、Enterでは通常の未完成ローマ字と同様に確定する。

- UTF-8（BOMあり／なし）、LF／CRLF。空行を無視する。
- `#` から始まりタブを含まない行はコメント。各列の空白は削らない。
- ファイルは256 KiB、独自ルールは2048件まで。
- 入力は1〜16文字の印字可能ASCII。大文字を含むルールは使わない。
  英字のShiftは変換開始・送り境界に使い、小文字へ直してルールへ渡す。
- `q`・`l`・`/`・空白で始まるルールは予約操作と衝突するため拒否する。
  `zl`・`z/`・`z ` のように途中へ含めることはできる。
- 出力は1〜64 Unicode文字。空文字・制御文字・埋め込みオブジェクト文字は禁止。
- 3列目は、未完成の入力として継続可能なプレフィックスに限る。
- 同じ入力の重複や、完成したルールが別のルールの先頭になる設定は拒否する。
  例えば既存の `ka` に対し `k` →「く」を加えると、`ka` へ到達できなくなるため拒否する。
- 不正UTF-8や不正行があれば、ファイル全体を不採用にする。一部だけの適用はしない。

## 内蔵ルールとDDSKKとの相違

訓令式・ヘボン式の主要なかな、促音、小さいかな、撥音に加え、`she`・`je`・`che`・`thi`・`dhi`・
`tsa`・`tsi`・`tse`・`tso` などの外来音と `xwa`・`xka`・`xke`・`xn` を使える。
`zh/zj/zk/zl` は矢印、`z.` は三点リーダ、`z,` は二点リーダ、`z/` は中点、
`z[` / `z]` は二重かぎ括弧、`z` → Spaceは全角空白になる。
通常の読みの後のSpaceは、引き続き辞書変換を行う。

この設定はDDSKKの「入力・出力・持ち越す入力」の考え方を参考にした独自形式。
DDSKKのLispファイル、関数を呼ぶルール、かな／カナで別々の出力、ルールの削除、
空出力によるプレフィックス定義、`zL` のような大文字を区別するルールには対応していない。
AZIKやTUT-codeの完全な定義としては使わない。モードキーの変更も別の課題。

`nn` は既存の入力感を保つため、内蔵では2番目の `n` を次の音節にも使う。
`konnichiha` →「こんにちは」、`hannou` →「はんのう」となり、末尾の `nn` は「ん」1文字。
DDSKKの既定の `nn` は2文字を消費する。合わせたい場合は `nn<TAB>ん` を追加する。
3列目に `n` を明示したルールでは、その `n` は通常の未完成入力なので、Enterでさらに「ん」となる。
内蔵の `nn` が持つ末尾の重複抑制とは異なる。

ルールで処理できない入力はASCIIとして残す。Shiftを離す遅れの許容は従来どおりで、
`KAnji`・`KOroNde`・`KaKU` の境界処理は維持する。

参照: [DDSKKのローマ字ルールの設定](https://ddskk.readthedocs.io/ja/latest/06_apps.html)、
[DDSKKの基本的な入力](https://ddskk.readthedocs.io/ja/latest/05_basic.html)。

## 開発用の上書き

`NSKKZIME_ROMAJI` に絶対パスを指定すると保存設定より優先する。`builtin` は内蔵ルールを強制する。
`NSKKZIME_DICTIONARY` を使った隔離設定では保存されたローマ字設定も読まないため、
併用したい場合は `NSKKZIME_ROMAJI` を明示する。
`skk_trace --romaji` は明示したファイルだけを使い、Windowsの保存設定や環境変数は読まない。
