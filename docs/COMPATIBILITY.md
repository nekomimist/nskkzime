# 対応範囲とOS・アプリの制約

2026-10-09時点。配布対象は **Windows x64、zenz CPU入りの一種類**。
以下はソース・成果物・実測の区別を付けた対応表であり、未検証環境で使えるという宣言ではない。
zenzのCPU/OS要件は起動前に検査する。検査項目と、この端末以外の未実測範囲は [CPU対応](CPU_SUPPORT.md) を参照。

| 環境 | 現状 | 根拠・残作業 |
|---|---|---|
| Windows 11 x64、標準EDIT／TSF対応RichEdit | 基本入力、辞書変換、実モデル連携を確認済み | 親context対応で標準EDITの矢印・クリック・ドラッグと文脈を確認。読みは補助欄に表示し、ホスト側本文変更後の入力も確認した。Program Filesの `ef1be87` へ登録を更新し、標準EDITの読み・矢印・継続入力とRichEditの実モデル採点・確定を再確認。[TSF検証](TSF_VALIDATION.md) を参照。全機能・全入力操作の確認ではない |
| Edge／Chrome／Firefox | ユーザーによる修正後の変換成功の報告あり | 通常デスクトップ側の設定を修復した後、3ブラウザーとも問題が解消したとの報告。[設定保存先の修正](INSTALLATION.md#2026-10-07の設定保存先の修正)を参照。全入力欄・全機能の検証ではない |

| Excel (x64) | 属性不明への対応後、zenz生成候補の表示・セルへの確定を確認済み | 登録版 `3b6b753` で「もんだいなさそう」から「問題なさそう」を生成・確定した。文脈許可を有効にしても、今回のF2によるセル内編集では短い前置き・長めの文章途中とも周辺本文なし。文脈取得は改善項目とし、数式バー編集・別セルは未検証 |

| Windows on Arm／ARM64アプリ | 現在の配布対象外 | ARM64／ARM64EC成果物を提供せず、x64エミュレーション上のIME・推論も未検証 |
| その他のAppContainer／UWPの入力先 | 対応対象外 | かな入力は可能でも、補助プロセスの許可対象ではなく設定・辞書・zenzへ接続できない。追加するパッケージごとに検証が必要 |

## x86とARM64

TSF DLLは入力先プロセスへ読み込まれる。32ビットプロセスは64ビットDLLを読み込めないため、
現在のAMD64 DLLを置いただけではx86アプリ向けの実装にはならない。
別プロセスのIPCはビット数をまたげるが、TSF DLLの制約は別である。
[Microsoftのプロセス相互運用仕様](https://learn.microsoft.com/en-us/windows/win32/winprog64/process-interoperability)を参照。

Windows on Armにx64エミュレーションがあっても、それだけでネイティブARM64の入力先へこのDLLを
組み込めるとは判断しない。DLLの構成、登録先、zenzのCPU命令と実モデルの性能を実機で確認する必要がある。
[MicrosoftのArmエミュレーション説明](https://learn.microsoft.com/en-us/windows/arm/apps-on-arm-x86-emulation)を参照。

## AppContainer

MicrosoftのIME要件では、IMEは読み込み先アプリのAppContainer制約を受け、互換性の宣言には
`GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT` を使う。XAML Islandsは通常のデスクトッププロセスも
immersiveモードにするため、nskkzimeは既存の4カテゴリーにこの宣言を追加する。
`ActivateEx` の先頭で実トークンを確認し、AppContainerでは専用の補助プロセスを利用する。
トークンを判定できない場合は失敗を返し、デスクトップのファイル・IPC経路へ代替しない。
[MicrosoftのIME要件](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements)を参照。

| 対象 | 現在のコード | 制約 |
|---|---|---|
| DLL・設定・辞書 | 公開プログラムだけAppContainerの読み取りを許可。設定と辞書のスナップショットはbrokerから非同期取得 | brokerは通常権限で起動。私用ファイルのACLは変更しない |
| 辞書キャッシュ | コンパイル済み辞書イメージをメモリーに読み込む | 初期取得中はかな入力のみ。broker再起動・設定変更後は入力先アプリを起動し直す |
| 学習・推論IPC | 許可したパッケージSID、ユーザー、セッションを照合してbrokerが既存の補助プロセスへ中継 | 任意ファイルの読み書き・任意コマンドの実行は提供しない。パスワード・属性不明の扱いは既存と同じ |
| 候補UI・設定／辞書GUI | 候補UIとTSF UIElementを利用。AppContainerから管理GUIは起動しない | 検索UIへの候補統合とタッチキーボードは未検証 |

コンテナー内の `LOCAL` パイプ名と、デスクトップ側のセッション・コンテナーSID付きパイプ名を対応させる。
接続先の実行ファイルもIME DLLと同じディレクトリーのbrokerに限定する。
[AppContainer設計と検証](APPCONTAINER.md)を参照。

## 入力属性と外部アプリの検証

パスワード・private・PIN等の属性では、文脈取得・推論・学習を抑止する。
属性不明では既定で読みだけをローカル推論に渡し、明示設定で文脈も利用できる。学習・単語登録・入力ログは抑止する。
これはコア／TSFテストで確認しているが、各アプリが属性をどう提供するかは実測が必要。
外部アプリの検証では、通常入力と保護入力を分け、変換、取消、マウス／矢印移動、貼り付け、
別欄移動、サーバーの遅延／停止、確定後の学習を確認する。
確認結果は [TSF検証の機能別表](TSF_VALIDATION.md) に追記する。
