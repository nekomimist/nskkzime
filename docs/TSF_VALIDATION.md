## 2026-10-07: 入力モードアイコンの右クリック

ユーザーから右クリックが反応しないと報告があり、`ModeButton::OnClick` が右クリックを何もせず返す実装だった。
メニュースタイルの宣言と左クリック通知による切替の実装も不一致だったため、ボタンスタイルへ統一し、
右クリックではIMEが所有するWin32ポップアップメニューを表示するようにした。
左クリックのオン／オフ切替は維持し、メニュー選択後は既存のモード変更・GUI起動処理へ渡す。
仕様の参照: [ITfLangBarItemButton](https://learn.microsoft.com/en-us/windows/win32/api/ctfutb/nn-ctfutb-itflangbaritembutton)、
[TrackPopupMenuEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-trackpopupmenuex)。

Releaseの52/52テストが成功（182.15秒）。右クリックから設定へ到達する経路、メニューの取消、
使用不可の項目、二重表示の防止、表示中の非表示化・IME解除後の選択抑止、メニューハンドルの解放を検査した。
入力検証アプリのモードボタンにも右クリックの通知経路を追加し、実画面でメニュー表示、
「設定…」から隔離設定を引き継ぐGUI起動、メニュー外クリックによる取消、左クリックの「あ→A」を確認した。
検証用の辞書・設定のみを使用し、日常用の辞書を読み取っていない。
記録は `out/mode-menu-20261007/`。タスクバーはComputer Useの対象ウィンドウとして取得できず、
タスクバーからの通知そのものは未実測。検証アプリでの成功と区別する。

旧登録版の設定GUIは通常デスクトップ側から直接起動し、ユーザーが「文脈」の設定を完了した。
修正コミット `6b19198` から全配布バイナリを再ビルドし、ソース変更なしのメタデータと16ファイルの整合性を確認した。
ユーザーがUACを承認し、manifest
`310da9afbe5d4ab02d4de8e16f1c09c27ea971950f825025681808259f2ec453`
のProgram Files配置版へ登録更新を完了した。保留中の更新がないことと、登録DLLのハッシュが配布物と一致することを照合した。
利用中のアプリは完全に終了して起動し直すと更新される。設定・辞書・モデルは登録更新では変更していない。

## 2026-10-07: 属性不明の文脈利用設定

CLIの `--set-zenz-unknown-context` を追加した。対象と前後範囲の属性不明を明示的に許可できるが、

通常権限で新規起動したWordの空文書と、別インスタンスのExcelの検証用CSVで、

## 実入力の確認手順

開発用DLLは候補一覧・注釈と、あ／ア／Aの入力モード項目を提供する。
モード項目のシステムトレイ表示には、対応カテゴリーを含む新しい版での登録が必要。
以下はPhase 0の作業手順。ビルドスクリプトからは実行しない。

1. Releaseをビルドする。最初は開発用Windows環境で確認する。
2. 管理者PowerShell 7から `scripts/register-dev.ps1` でDLLを登録する。
3. 通常権限のPowerShellから辞書の環境変数を設定し、`ime_probe.exe` を起動する。
4. 日本語入力言語の状態で「nskkzimeを選ぶ」を押す。このアプリのプロセス内だけで切り替える。
5. 下の一覧を実行し、アプリ名・版・結果を記録する。
6. 別IMEへ切り替え、使用中アプリを閉じてから登録解除する。

```powershell
# 管理者PowerShell 7、リポジトリのルートで実行
.\scripts\register-dev.ps1

# 通常権限のPowerShell、リポジトリのルートで実行
$env:NSKKZIME_DICTIONARY = (Resolve-Path .\SKK-JISYO.utf8.L).Path
.\out\build\windows-x64-zenz\Release\ime_probe.exe

# 入力検証アプリ等を閉じてから、管理者PowerShellで登録解除
.\scripts\register-dev.ps1 -Unregister
```

登録はこのプロジェクト専用CLSID `{6EF45A57-E12E-49F1-8A4E-2569D8361A50}` と
日本語プロファイル、キーボード・表示属性・入力モードコンパートメント・システムトレイ対応のカテゴリーを使用する。
プロファイルを有効化するが、既定IMEは変更しない。別のビルドを誤って上書きしないよう、
CLSIDが既に登録済みなら登録を拒否する。登録先のDLLを変更する前に、元のDLLで解除する。
新しい実装の `DllUnregisterServer` はHKLMの `InprocServer32` と実行中DLLの絶対パスを
大文字小文字を区別せず比較し、別のパスなら `ERROR_NOT_OWNER` を返してTSFを変更しない。
未登録なら何もせず `S_FALSE`、欠損・型違い・終端不正等で所有元を確認できなければ失敗する。
登録・解除は共通の名前付きmutexで直列化し、処理中の別呼び出しは `ERROR_BUSY` で終了する。
この保護を持たない旧DLLや、レジストリへの直接操作との排他までは保証しない。

登録中の失敗では実行を試みたTSF操作を巻き戻す。後始末にも失敗した場合は、解除を再試行できるよう
COMの登録先を残して失敗を返す。解除中のカテゴリー・プロファイル操作の失敗も無視せず、
登録先を残す。再試行ではWindowsの列挙APIで既に存在しない項目を確認してから飛ばす。
これは各操作の失敗を検出する処理であり、OS全体に対する原子的な更新や旧版の自動復元ではない。
新しいDLLでの実OS登録・解除と、権限／OS側障害からの復旧の実測は引き続き必要。
アンインストーラー・署名・更新処理はPhase 3で実装する。

登録スクリプトは `stage-dev.ps1` を使い、zenz入りReleaseのDLL・辞書補助プロセス・設定GUI・辞書管理GUI・推論サーバーを同じ
`out/installed/<5ファイルの名前とハッシュから作ったSHA256の先頭16文字>/` へコピーしてから登録する。
5ファイルを事前に検査し、配置後にもハッシュを照合する。同一内容の配置は再利用し、既存ファイルは上書きしない。

### 既知の制限

標準EDITの矢印・クリックの制限は、親contextを利用する上記Releaseで改善した。
