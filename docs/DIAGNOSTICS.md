# 明示設定による入力ログ

入力ログは既定でオフ。保存先だけ設定しても有効にならない。
変換の調査が必要なときに、設定GUIの「診断」タブで「入力ログを保存する」をオンにし、
作成済みのローカルフォルダーを指定して保存する。設定の検査・保存だけではログファイルを作らない。
有効化・無効化とも、IMEを使うアプリを終了して起動し直すと反映される。
現在起動中のアプリは読み込み済みの設定を使い続ける。

CLIでも明示的に切り替えられる。

```powershell
# 作成済みフォルダーを指定する。読み・前後の本文・候補が平文で保存される。
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --enable-input-log 'C:\my-diagnostics'
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --disable-input-log
```

保存設定は `input-log=on|off` と `input-log-directory=<絶対パス>`。
推論がオフなら記録せず、`--disable-inference` はログ設定もリセットする。
`--disable-input-log` は保存先を保持したまま無効化する。どちらも既存ログを削除しない。
開発用のダミー環境変数を使う経路では、保存設定のログを有効化しない。

## 記録する範囲

IME側で、現在の入力欄・composition・本文・世代・入力属性を照合できた推論応答を記録する。
本文を反映した後も属性と周辺文脈を確認する。対象は変換要求の読み、前後各最大40文字、
採点対象の辞書候補、推論結果の候補・スコア、応答状態、書き込み時のUTC日時とPID。
UTF-8 JSON Linesで、各行に `format=nskkzime-input-log` と `version=1` を含める。
改行・引用符等を含む本文はJSONとしてエスケープする。

パスワード・private・PIN・属性不明の欄、入力状態が変わって破棄した応答、本文への反映に失敗した場合は保存しない。
通常入力で時間切れやサーバー失敗から復帰した場合は要求と状態を記録し、応答本文は `null` にする。
候補順位が変わらなかった正常応答も記録する。
保存済みの通常入力を後から取り消しても、そのログは残る。
これは全キー操作や文書全体、最終的に確定した候補を記録する仕組みではない。

記録はIMEクライアント側に置き、共有した推論サーバーにログを一括設定しない。
同じサーバーを使う別アプリでも、それぞれの設定がオフなら記録しない。
入力欄の実際の属性提供状況はアプリごとの検証が必要であり、対応範囲は [互換性表](COMPATIBILITY.md) を参照。

## 保存・上限・失敗

- 入力スレッドでは最大8件の待ち行列へ渡すだけ。JSON化とファイル操作は推論の作業スレッドで行う。
  推論要求を優先するが、診断を有効にした場合のファイルI/Oは以後の要求の処理時刻に影響し得る。
- `nskkzime-input-<ランダムID>.jsonl` を新規作成する。既存ログへ追記したり、上書き・自動削除したりしない。
  作成時のDACLは継承を止め、実行ユーザーSIDにアクセスを許可する。暗号化ではない。
- 1ファイル1 MiB、同じフォルダーに上記の名前のJSONLが64個まで。作成をファイルロックで直列化し、
  複数プロセスでもファイル数を確認してから追加する。既存ファイルは復旧や容量確保のためにも自動削除しない。
- UNC／ネットワークドライブ、祖先を含む再解析ポイント、存在しないフォルダーを使わない。
  保存先エラー・ファイル数／容量上限ではそのIMEクライアントの記録を停止し、変換を継続する。
- 待ち行列が満杯なら追加分を保存しない。終了時の未保存分も破棄する。異常終了やディスク障害では
  最後の行が不完全になる場合があるため、完全な入力履歴・監査ログとしては使わない。

ビルド版の検証アプリの推論診断には、ログのオフ／待機／保存中／上限停止／保存不可と、待ち行列から除外した件数を表示する。
ログを削除する場合は利用アプリを閉じ、必要なものを残して対象のJSONLだけを削除する。
補助の `nskkzime-input-log.lock` には本文を保存しない。

## 検証

`settings`／`settings_editor`／`config_cli` で既定オフ、パスだけでは有効にならないこと、明示した切替、
保存・再読込、既存設定の保全を確認する。
`input_log` でJSONの往復、改行のエスケープ、ユーザーSIDのDACL、上限、既存ファイルの保全、
保存先不在・競合時の停止、非同期キューを確認する。
`tsf_inference_policy` で通常入力のログ、private・password・PIN・属性不明、途中の保護属性変更、
取消・編集拒否、反映直後の保護属性と再起動後の無効化を確認する。
全て隔離したテスト用設定とファイルを使い、利用者のログ設定は変更しない。
2026-10-07に `d5847b1` の設定GUIを隔離した `--config` で起動し、診断タブを実画面で確認した。
入力ログがオフの表示、保存済みのフォルダーパス、無効なパス編集欄・参照ボタン、
平文保存の範囲・上限・アプリ再起動の説明が表示された。
「検査する」で9見出し・33候補のfixtureを読み込み、推論・入力ログともオフと表示された。
設定ファイルの検査前後のSHA-256は同一、保存先のログは0件だった。
画面からの有効化・保存・再起動後の記録と、外部アプリでの確認は残る。

## 開発用の状態トレース

調査用プロセスに `NSKKZIME_STATUS_TRACE` を絶対ファイルパスとして渡すと、推論の固定状態メッセージ、
プロセスID・スレッドID・起動後時刻をUTF-8で追記する。読み・候補・周辺本文・要求／応答は含めない。
通常は未設定で、上記の診断用入力ログとは独立している。入力属性不明による停止などの切り分けに使う。
ファイルが64 KiB以上なら追記を停止し、保存失敗でも変換を継続する。開発用の同期記録であるため、
常用設定には追加せず、指定プロセスだけで利用する。`inference` テストで無効時・相対パス・明示指定・上限・保存失敗を確認する。
