# 導入・更新管理

`scripts/install.ps1`（配布ZIPでは `tools/install.ps1`）は、zenz入りの形式2・3パッケージを
`%ProgramFiles%\nskkzime\versions\<マニフェストのSHA-256>` へ配置して登録する開発用スクリプト。
利用者向けコマンドは [パッケージの手順](PACKAGE_README.md) を参照。
リポジトリーからは `-Action Install -PackageDirectory <検査済みZIPの展開先>` を指定する。

## 対象と保全

- x64 PowerShell 7、Windows x64、本人の管理者トークンで実行する。`Status` のみ通常権限で使える。
- 配置先は固定。新規ルートはSystem／Administratorsのみ書き込み可能なDACLで作り、UsersとALL APPLICATION PACKAGESには読み取り・実行を許可する。
  再利用するルートと子孫も所有者・書き込み権限・再解析ポイントを照合する。旧版からの更新では、この公開プログラム用ルートに限りAppContainer向けの読み取り・実行ACEを追加する。
- パッケージを検査後、専用の一時フォルダーへ固定一覧だけコピーし、再検査してから版フォルダーへ移す。
  コピー中の変更を拒否し、既存の版は一致する場合だけ再利用する。失敗した一時配置は診断用に保持する。
- HKCUの同一CLSID、壊れたHKLM登録、管理外のDLL登録は拒否する。開発用登録からの移行は元の手順で先に解除する。
- 設定・辞書・モデルに触れず、配置した旧版も削除しない。サーバーの絶対パス設定は別途GUIで変更する。
  新旧プロセスが混在しないよう、利用アプリを閉じて操作し、終了後に起動し直す。
- 形式3では本人のHKCUのRunに `nskkzime broker` を登録する。登録先の変更とRun設定は同じ復旧記録で管理し、
  解除・形式2への復帰ではRun登録を外す。成功後に旧brokerを停止し、通常権限のExplorerから新brokerを起動する。
  起動できなかった場合も登録先は有効で、次回サインインで起動する。管理者権限で常駐させない。

## 失敗と中断

`operation.lock` を共有不可で開き、同じ配置先の操作を直列化する。登録はWindowsの `regsvr32 /s`、
解除は `/u /s` を使い、終了コードに加えてCLSIDの登録先を毎回読み直す。
操作前に新旧両方の全ファイルを検査し、`transaction.json` に変更前と変更後の版IDを書いてフラッシュする。

更新に失敗した場合は変更前の状態への復帰を試みる。部分的な解除で旧版のCLSIDだけが残っていても、
旧版を再度解除してから登録し、途中で外れたTSFカテゴリー等を修復する。
復帰失敗や処理の中断では記録を残し、次の `Install`／`Rollback`／`Unregister` を拒否する。
`Recover` は記録された変更前の状態に戻す。初回導入が中断した場合は未登録へ戻す。
記録した新旧以外の版や管理外の登録へ変わっていれば操作しない。

稼働中の `regsvr32` がある場合は登録操作・復旧を開始しない。子プロセスを途中で強制終了しない。
これはOS全体の原子的なトランザクションではない。別経路の登録変更との全ての競合、電源断、
ファイル破損、管理者による変更から必ず回復できるとは限らない。記録や復旧元DLLを手動削除しない。
ハッシュは整合性の検査であり、署名や提供者の認証の代わりにはならない。

## 検証の境界

`installation` CTestはReleaseパッケージを日本語・空白を含む一時パスへ配置し、登録呼び出しだけを
模擬処理へ差し替える。正常な導入・更新・解除・旧版復帰、共有不可ロック、登録／解除の途中失敗、
成功コードなのに登録先が変わらない場合、復帰失敗後の再開、中断の各状態、管理外登録への途中変更、
旧版／新版の破損、不正な更新記録、設定相当ファイルの保全を確認する。形式2との相互更新とRun書き込み中断からの復旧も確認する。実レジストリとTSFは変更しない。
DebugではReleaseのパッケージがないためこのテストをスキップする。

実OSの初回導入・更新・復帰は下記の端末で確認した。後続の確認ではProgram Files版へ実登録し、
入力検証アプリ・実モデル採点・サーバーCLI生成・隔離設定での設定GUI起動と検査も確認した。
クリーンWindows、複数ユーザー、UACで別アカウントを使う構成は未検証。
「インストールされているアプリ」への登録、GUIインストーラー、自動更新、旧版の自動削除はまだ提供しない。

## 2026-10-07の実OSでの導入・復旧検証

Windows 11 x64の開発端末で、本人のPowerShell 7をUAC承認により昇格して実行した。
`95d442a` のzenz入りZIPを版A、`ef1be87` を版Bとし、版Bに同梱した導入・検査スクリプトを使用した。
両ZIPと展開先を検査してから、実際の `regsvr32` とHKLM登録先を使って次を確認した。

- 管理外の開発用登録がある状態では、解除も配置先作成もせずに導入を拒否する。
- 開発用登録を元DLLで解除後、版AをProgram Filesへ初回配置・登録できる。
  ルートの所有者はAdministrators、System／Administratorsのみ書き込み可能、Usersは読み取り・実行だった。
- 同じ版Aの再導入は `Unchanged` となり、版Bへの更新で登録先が版Bへ移る。
- `Rollback` で版Aへ戻り、`Unregister` で登録が消える。両版のファイルは保持される。
- 版Bを登録した状態で「変更前A・変更後B」の更新記録を作り、`Recover` が版Aへ戻して記録を除去する。
  中断後に残る状態を作った検証であり、実際にプロセスを強制終了したり電源を切った試験ではない。
- 最後に管理下の登録を解除し、検証前の開発用DLLを再登録する。
  終了後に通常権限で登録先・元DLLのハッシュ・未完了記録なし・配置済み両版の全ファイルを再確認した。

## 日常利用の登録先への切り替え

上記の復旧試験後、ユーザーの指示とUAC承認により版B（`ef1be87`）を実際の登録先にした。
この操作では成功後も版Bを保持し、現在の登録はProgram Files内の版Bを指している。
未完了の更新記録はない。変更前の開発用DLLと配置した版Aも保持している。
記録は `out/daily-use-a6ed4296337640ea8b93e621b0e72b39/activation-result.json`。

日常用設定は同じフォルダーの `settings.before.ini` へバックアップし、既存の辞書指定を保持して
手元のzenzモデル・配置版サーバー・候補採点を有効にした。入力ログはオフ。
この最初の保存は後述のAppData仮想化によりアプリ専用の保存先だけに反映されていた。
通常デスクトップ側への反映は、同日のブラウザーでの問題報告後に修正・検証した。
登録版での確認内容は [TSFの検証](TSF_VALIDATION.md) に記載する。
既に起動している入力先アプリは、古いDLLや設定を保持する場合があるため再起動する。
既定IMEの自動変更は行っていない。Windowsの入力方式からnskkzimeを選び、`C-j` でかな入力にする。

## 2026-10-07の設定保存先の修正

ユーザーから、Windows版ChatGPTでは変換できる一方、通常のEdge／Chromeのアドレスバーでは
`Kanji` →「漢字」だけ通り、`Uta`・`KoroNde` がかなのままになると報告された。
通常デスクトップからの調査では登録DLLはProgram Filesの `ef1be87` で、既定の `settings.ini` が存在しなかった。
設定なしの場合は5見出しの内蔵テスト辞書を使い、zenzも無効になる。「かんじ」はこの辞書に含まれるが、
「うた」「ころn」は含まれず、報告された差を説明できる。

開発側で `C:\Users\hiro\AppData\Local\nskkzime\settings.ini` を開いたハンドルを
`GetFinalPathNameByHandleW` で調べると、実体は
`AppData\Local\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\nskkzime\settings.ini` だった。
絶対パスの指定や開発側での読み戻しだけでは、他のデスクトップアプリへの反映確認にならない。
この動作の背景は [Microsoftのパッケージアプリの仮想化の説明](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes) を参照。

Explorerのデスクトップ環境から非対話の補助スクリプトを起動し、通常側に設定がないことを再確認してから
既存の辞書・zenz設定を新規作成した。コピー元は保管し、既存ファイルの上書きは拒否した。
作成したハンドルの実体が通常のAppDataであること、設定のハッシュがコピー元と一致すること、
配置版 `nskkzime_config.exe --show` が環境変数の上書きなしで外部辞書・zenz・候補採点を認識することを確認した。
ユーザーのSKK辞書の本文は調査・変更していない。記録は `out/browser-config-20261007/`。
DLL登録は変更していない。起動済みの利用アプリは終了・再起動すると設定を読み直す。
ブラウザー内での修正後の実入力は、この設定確認とは別に扱う。

設定の導入・検証は、通常のデスクトップから起動した設定ツールでも行う。
2026-10-09の修正では、仮想化される入力先のIMEは通常権限brokerから設定を受け取り、
設定GUIもbroker経由で通常の保存先を開く。古いアプリ専用コピーは保持し、自動移行・削除はしない。
