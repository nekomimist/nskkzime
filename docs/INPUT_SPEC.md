# 最初の入力仕様

これは現在の実装の仕様であり、DDSKK完全互換を示すものではない。
コア内の文字列はUnicodeコードポイント（UTF-32）、TSFとの境界でUTF-16、CLIでUTF-8へ変換する。
`Mode` はHiragana / Katakana / Latin、`Stage` はDirect / Reading / Okuri / Selecting。

## キー操作

| 入力・状態 | 動作 |
|---|---|
| 通常の小文字 | 完成したかなを順に確定。未完成のローマ字だけ保持 |
| 大文字 | 読み入力を開始。読みがある場合は送り仮名を開始 |
| 読み入力中のSpace | 辞書を検索。末尾の `n` を「ん」にする |
| 送り仮名が完成 | 語幹の読み＋送り開始の英字を見出しとして辞書を検索 |
| 候補選択中のSpace | 次候補。最後では `candidates_exhausted` を通知して位置を保持 |
| 候補選択中の `x` | 前候補。先頭では読み入力へ戻る |
| Enter | 表示中の候補、または読みを確定 |
| 候補選択中の通常文字 | 候補を確定し、その文字を新たな入力として処理 |
| `C-g` / Escape | 候補から読みへ戻る。読み入力中なら取り消す |
| Backspace | 候補から読みへ戻る／未完成ローマ字・読み・送りを編集 |
| 未完成ローマ字がないときの `q` | 通常入力ではかなモード切替。読み入力では反対のかな種で確定 |
| 通常入力で未完成ローマ字がないときの `l` | Latinモードへ移行 |
| `C-j` | 未確定入力を確定し、Hiraganaモードへ移行 |
| Latinモード | `C-j` 以外は入力先アプリへ渡す |
| 未確定入力がないEnter / Space / Backspace / Escape | 入力先アプリへ渡す |

撥音は `n`＋子音、`n'`、末尾の `n`、`nn` に対応する。
`nn` の二つ目の `n` は次の音節に使えるよう保持するため `konnichiha` →「こんにちは」となる。
未対応のローマ字は黙って捨てず、ASCIIとして残す。全ローマ字表やDDSKK互換は今後比較する。
辞書にない読みは保持する。単語登録UIは未実装で、Enterでかなのまま確定できる。

## fixtureで固定した例

| キー列 | 結果 |
|---|---|
| `Kanji<Space>` | `▼漢字` |
| `Kanji<Space><Space><Enter>` | 「感じ」を確定 |
| `Kanji<Space>desu` | 「漢字です」を確定 |
| `KaKu` | `▼書く` |
| `KaKu<Space><Enter>` | 「描く」を確定 |
| `TaBeru` | 「食べる」を確定 |
| `Nihon<Space><Enter>` | 「日本」を確定 |
| `Kanji<Space><C-g>` | `▽かんじ` |
| `Kanji<Space><C-g><C-g>` | 確定せず取消 |
| `Michi<Space><Enter>` | 未登録のため「みち」を確定 |

## コアとOSの契約

`would_handle` は読み取り専用。`handle` はキーを消費したかと確定文字列を返す。
Windows側は次状態をコピー上で計算し、文書編集が成功してから採用する。
候補マーカー `▽` / `▼` と送り境界 `*` は未確定表示にだけ含める。
候補を確定した文字列にマーカーを入れない。

将来の非同期推論は、このコアへイベントとして結果を渡す。COMオブジェクトを
推論スレッドへ渡さず、入力欄と世代を確認してからTSF編集セッションで反映する。
