# 最初の入力仕様

これは現在の実装の仕様であり、DDSKK完全互換を示すものではない。
固定版DDSKKとの38例の実測と初版の対応範囲は [DDSKKとの操作比較](DDSKK_COMPATIBILITY.md) に記録する。
コア内の文字列はUnicodeコードポイント（UTF-32）、TSFとの境界でUTF-16、CLIでUTF-8へ変換する。
`Mode` はHiragana / Katakana / Latin、`Stage` はDirect / Reading / Okuri / Selecting / Registering。
abbrevは読みの入力方法として別に保持し、かなモードと候補選択の状態を流用する。

## キー操作

| 入力・状態 | 動作 |
|---|---|
| 通常の小文字 | 完成したかなを順に確定。未完成のローマ字だけ保持 |
| 大文字 | 読み入力を開始。完成した読みがある場合は送り仮名を開始。最初のかな・送り仮名の入力途中では小文字として継続 |
| 読み入力中のSpace | 辞書を検索。末尾の `n` を「ん」にする |
| 送り仮名が完成 | 語幹の読み＋送り開始の英字で検索し、入力した送り仮名の候補ブロックを優先 |
| 候補選択中のSpace | 次候補。最後では単語登録へ。登録が無効な場合は最後の候補を保持 |
| 候補選択中の `x` | 前候補。先頭では読み入力へ戻る |
| 候補選択中の `X` | 学習語の削除確認を開く。`yes`＋Enterで削除、Escape／C-g／`no`＋Enterで候補へ戻る |
| 候補選択中のPageDown / PageUp | 7候補分ずつ次／前へ移動。範囲外へ出る場合は末尾／先頭で止める |
| 候補選択中の `1`〜`7` | 表示ページの該当候補を確定。登録欄内では欄へ追加して入力を続ける。存在しない番号は状態を保持 |
| Enter | 表示中の候補、または読みを確定 |
| 候補選択中の通常文字 | 候補を確定し、その文字を新たな入力として処理 |
| `C-g` / Escape | 候補から読みへ戻る。読み入力中なら取り消す |
| Backspace | 候補から読みへ戻る／未完成ローマ字・読み・送りを編集 |
| 未完成ローマ字がないときの `q` | 通常入力ではかなモード切替。読み入力では反対のかな種で確定 |
| 通常入力で未完成ローマ字がないときの `l` | Latinモードへ移行 |
| 通常入力で未完成ローマ字がないときの `/` | abbrev入力を開始 |
| `C-j` | 未確定入力を確定し、Hiraganaモードへ移行 |
| Latinモード | `C-j` とWindowsのモード切替キー以外は入力先アプリへ渡す |
| 未確定入力がないEnter / Space / Backspace / Escape | 入力先アプリへ渡す |

撥音は `n`＋子音、`n'`、末尾の `n`、`nn` に対応する。
`nn` の二つ目の `n` は次の音節に使えるよう保持するため `konnichiha` →「こんにちは」となる。
未対応のローマ字は黙って捨てず、ASCIIとして残す。外来音・小さいかな・`z` に続く記号入力も扱う。
`z` → Spaceは全角空白、`zh/zj/zk/zl` は矢印となる。これらは辞書変換の前に処理する。
UTF-8の独自ルールで追加・上書きでき、登録欄や送り仮名でも同じルールを使う。
形式・上限・DDSKKの `nn` との違いは [ローマ字ルール](ROMAJI.md) を参照。
辞書にない読みでは単語登録へ入る。空のままEnterを押すと読みに戻り、さらにEnterでかなのまま確定できる。
Windowsでは学習が無効・辞書読み込み失敗などの場合は登録を開始せず、読みを保持する。

Shiftを離すのが遅れた場合に備え、変換開始後の最初のかなが完成するまでは、続く大文字も
同じローマ字の一部として処理する。`KAnji` は `Kanji`、`KYOu` は `Kyou` と同じになる。
送り仮名の開始後も大文字でローマ字を区切らず、`KaKU` は `KaKu`、`KOroNde`／`KOroNDE` は
`KoroNde` と同じになる。後者は外部辞書の `ころn /転/` があれば「転んで」に変換する。
時間による判定は行わない。完成した読みの後の大文字は引き続き送りの開始なので、
`AI` は「あ」を読み、「い」を送りとして検索する（候補がなければ単語登録へ）。
`KAnJI` の `J` では直前の `n` を「ん」として読みに含め、送りを始める。
この許容範囲はDDSKKの `skk-set-henkan-point` にある `KAnji`／`KanJIru` の考慮を参考にした。
読みの途中でShiftを押す位置が遅れる `ArukU` など、DDSKKのその他の補正は未実装。

## Windowsの入力モード

TSFの入力モード項目として「あ」（ひらがな）・「ア」（カタカナ）・「A」（英数／IMEオフ）を提供する。
メニューで3つのモードを選択でき、Windowsの開閉・変換モードと `q`／`l`／`C-j` の結果を同期する。
初回の起動時にWindowsの開閉状態があれば引き継ぎ、状態がまだなければひらがなで開始する。
システムトレイへの表示には新しい版でのIME登録が必要。検証アプリ右上のモードボタンでも同じTSF項目を表示・切替できる。
入力モードメニューには「設定…」「学習辞書の管理…」も用意し、IMEと同じ保存先を渡して別プロセスで開く。
これらの選択はモード変更を要求しない。起動処理は入力スレッドの外で行い、IME解除後の古いメニューからは起動しない。
検証アプリ右上のボタンはオン／オフ切替のみで、このメニューは表示しない。

- 半角／全角またはCtrl+Space: オン／オフ。オンに戻すときはひらがな。
- IMEオンキー: ひらがな。IMEオフキー: 英数。
- Shift／Alt／Windowsキーを加えた組み合わせは、この切替として処理しない。
- Windowsやモード項目から切り替えると、現在の本文を保持して未確定状態を終了する。候補の学習はしない。
  登録途中の語は破棄し、外側の読みを本文に残す。遅延した候補クリックも無効になる。
- 登録欄の中の `l` は欄内の英数入力であり、WindowsのIMEを閉じない。

## 周辺テキストの取得

推論接続に備え、TSFの読み取りロック内で変換範囲の前後を取得する処理を用意した。
上限は前後各40 Unicodeスカラー値。変換中の読み・候補・登録欄の本文は含めない。
UTF-16のサロゲートペアを保ち、不正な文字列・埋め込みオブジェクト・部分的な読み取りは取得失敗として扱う。
TSFの範囲境界を越える探索はしない。

対象がパスワード・private・PINの場合は周辺本文を読まず、推論もしない。
属性不明では既定で周辺本文を読まず、IMEが保持する変換中の読みだけでローカル推論を行う。
`zenz-unknown-context=on` を明示した場合は、対象と前後範囲の属性不明を許容して文脈を取得する。
前後の取得範囲も読み取り前に検査し、明示的な保護属性や読み取り失敗では空の文脈を使う。
実際の属性は不明のまま保持し、学習・単語登録・入力ログの許可へ変換しない。
通常属性の対象でも、属性不明の周辺範囲を含む推論要求は入力ログへ保存しない。
応答待ちの間に入力属性が変わった場合は、候補を反映しない。

通常は周辺本文を取得しない。推論が有効な場合は、要求時・応答適用時に文脈を取得する。
検証アプリの「文脈確認（本文を表示）」をオンにすると、候補選択・登録中の前後を画面へ表示する。
表示の設定と推論要求時の取得は独立している。この表示設定だけでは本文をファイル保存しない。
別の明示設定による [診断用入力ログ](DIAGNOSTICS.md) は既定オフで、入力属性と状態を再確認した推論応答だけを対象にする。
確定・取消・入力欄の切替・IME解除で取得結果を破棄する。検証をオフにした場合も直ちに破棄する。
RichEditでは前後文脈を取得でき、標準EDITの互換入力経路では前後とも空になることを確認済み。

## 内蔵fixtureで固定した例

| キー列 | 結果 |
|---|---|
| `Kanji<Space>` | `▼漢字` |
| `Kanji<Space><Space><Enter>` | 「感じ」を確定 |
| `Kanji<Space>2` | ページの2番目「感じ」を確定 |
| `Kanji<Space><Enter>2` | 「漢字2」を入力 |
| `Kanji<Space>desu` | 「漢字です」を確定 |
| `KaKu` | `▼書く` |
| `KAKU` | `▼書く`（Shiftを離す遅れを許容） |
| `KaKu<Space><Enter>` | 「描く」を確定 |
| `TaBeru` | 「食べる」を確定 |
| `Nihon<Space><Enter>` | 「日本」を確定 |
| `Kanji<Space><C-g>` | `▽かんじ` |
| `Kanji<Space><C-g><C-g>` | 確定せず取消 |
| `Michi<Space>Nihon<Space><Enter>` | 「みち」に対して「日本」を登録して確定 |
| `Michi<Space><Enter><Enter>` | 空登録から読みに戻り、「みち」を確定 |

外部辞書を指定したときの候補と順位はその辞書に従う。送り仮名別候補がある場合は
一致するブロック→通常候補の順で重複を除く。複数辞書は辞書の優先順を先に適用する。
例: `おおk /大/多/[く/多/]/[き/大/]/` では `OoKu` → `▼多く`、`OoKi` → `▼大き`。
注釈は候補データ・CLI出力・候補一覧に表示するが、未確定表示・確定文字列には付けない。

## abbrev（英字見出し）

通常のかな入力で `/` を押すと、英字見出しの入力を開始する。開始用の `/` は本文に入れない。
英大文字・英小文字・数字・記号をそのまま見出しへ追加し、大小文字を区別して通常の辞書を検索する。
abbrevの読み入力中は `q`、`l`、`x` も文字として入力し、大文字で送り仮名を開始しない。
例えば `skk /かな漢字変換/` という辞書なら、`/skk<Space><Enter>` で「かな漢字変換」となる。
内蔵テスト辞書には英字見出しがないため、変換の検証には外部辞書かテスト用ファイルを指定する。

- Spaceで変換し、候補選択中のSpace／x／Enterは通常のかな漢字変換と同じ。
- 候補からEscape／C-g／Backspace／先頭候補のxで戻ると、英字見出しの編集を続ける。
- 読み入力中のEnterは英字のまま確定し、Escape／C-gは取消。どちらもabbrevを終了する。
- Backspaceで最後の英字を消してもabbrevを保ち、空の状態でさらにBackspaceを押すと終了する。
- 確定・取消後は開始前のひらがな／カタカナへ戻る。C-jは確定してひらがなに戻る。
- 辞書にない場合は綴りを保って単語登録へ。補完・C-qでの全角化は未実装。

Windowsでは空のabbrevも長さ0のcompositionで入力位置を追跡する。カーソル移動や入力欄の切り替えで
abbrevを終了し、移動先に英字入力の状態を持ち越さない。本文へモードを示す文字は挿入しない。

## 単語登録

辞書に候補がない場合、または最後の候補からさらにSpaceを押した場合に登録を開始する。
Windowsでは本文に元の読みを残し、キャレット付近の別欄へ登録する語を入力する。
この欄のかな入力・漢字変換・abbrevは通常のSKK操作と同じ。`l` で英数入力、`C-j` でかなへ戻る。
Spaceや英数入力も登録欄が受け取り、入力先アプリへ流さない。

- Enterで登録欄全体を確定し、読みを登録した語へ置き換える。欄内の候補選択中でもEnterは1回でよい。
- 欄内の候補選択中に `1`〜`7` を押すと、その語だけを登録欄へ追加する。続けて入力でき、登録全体の確定にはEnterを使う。
- 空のままEnter、または欄内で変換中でないときのEscape／C-gで取り消し、元の読みへ戻る。
- 欄内で候補選択中ならEscape／C-gは候補から読みに戻る。もう一度でその読みを消し、さらに押すと登録を取り消す。
- Backspaceは未完成ローマ字、欄内の読み、入力済みの文字を末尾から編集する。空の登録欄では何もしない。
- 送りありの登録では語幹だけ入力する。確定時に元の送り仮名を付け、保存時は語幹と送りを分離する。
- 開始前のかなモード・abbrevの読みを保持し、確定・取消後に戻す。登録欄はひらがな入力で開始する。

登録欄で再び未知語を変換すると再帰登録へ入る。内側をEnterで登録すると、その語が外側の欄に追加される。
明示的に確定した内側の登録は、その後外側を取り消しても保存対象となる。
一方、欄内で既存の候補を選んだだけでは候補学習を行わない。
再帰は8段、各登録欄は1024コードポイントまで。上限を超えるキーは状態を保って受け止め、登録欄に上限を表示する。

登録後はTSF編集に成功し、入力属性が学習可能な場合にだけ保存用キューへ送る。
直後の再変換には入力コアの最大128候補の一時キャッシュも使い、保存の待ち時間に依存しない。
辞書スナップショットに同じ語が現れたら一時キャッシュから外し、以後は共有された候補順位に従う。
コアの試行コピーや編集失敗では辞書・キャッシュを更新しない。失敗したEnterは再試行できる。
入力属性がprivate・パスワード・取得不能の場合は登録を開始せず読みを保持する。
開始後に属性が変わった場合も保存直前に確認し、入力した語の確定だけを行って保存・一時キャッシュへの追加を見送る。
この理由は検証アプリの学習診断に表示する。

フォーカス移動・矢印・ショートカット・外部編集でcompositionを終了すると、未確定の登録欄を破棄する。
本文に残るのは元の読みで、登録欄の途中の文字列や案内文は挿入しない。
別欄を表示できない場合も読みに戻し、見えない登録欄へキーを取り込まない。
ホストがUIを引き受ける場合は `ITfUIElement` の説明に読み・登録内容・操作案内を返す。
登録欄そのものを `ITfCandidateListUIElement` の候補として扱わせない。

CLIでは `registration_depth`・`registered`・`registration_limit` と `learning` イベントを出力する。
登録した語はそのCLIセッション中だけ再利用し、ファイルへは保存しない。
`Engine(dictionary, false)` は登録を無効にし、従来どおり未知語の読みと最後の候補を保持する。
貼り付け・登録欄内のカーソル移動・注釈の入力は未対応。
登録語の一覧・削除・取り込み・書き出しは [辞書管理CLI／GUI](DICTIONARIES.md#登録学習した語の管理) から行える。

## 候補から学習語を削除

候補選択中の大文字 `X` は、選択した語の学習を削除する確認欄を開く。
語幹・読み・送りの範囲を表示し、小文字の `yes` を入力してEnterを押した場合だけ削除する。
Backspaceは確認文字列を編集する。Escape／C-g／C-j、または `yes` 以外でEnterを押すと候補選択へ戻る。
Spaceを含む文字列や `YES`、`y` は承認として扱わない。数字・候補クリック・ページ操作で候補を確定しない。
案内と確認文字列は本文へ挿入せず、成功後は元の読みを保って再変換できる。
DDSKKの `X` → `yes`＋Enterを参考にしたが、削除後に入力全体を消すDDSKKとはこの点が異なる。

送りありでは一致する送りの登録を優先し、なければ同じ送りキーの共通候補を対象にする。
確認開始時の対象を保持するため、その間に別アプリが辞書を変更しても別の送りの登録へ削除先を移さない。
共通候補や読み取り専用辞書にも同じ語があれば、削除後もその語は候補になる。候補を禁止する操作ではない。
未保存の登録語も対象にできる。登録欄内の候補にも使え、外側の読みと入力途中の登録内容を保持する。
CLIではセッション内の登録語に適用し、`forgetting` 状態と `forgotten` イベントを出力する。ファイルは更新しない。

Windowsでは学習が有効な場合に利用でき、対象がなければ理由を表示して候補へ戻す。
開始時と承認時に入力属性を確認し、パスワード・private・属性不明の欄からは削除しない。
本文の編集成功後だけ非同期の保存キューへ送る。保存中は通常入力を続けられ、失敗時は学習と同じ仕組みで再送する。
同じIMEの未保存学習・削除は受付順に検索結果へ反映するが、既に選択中の一覧は固定する。
保存状況と受付不可件数は検証アプリの学習診断で確認できる。
フォーカス移動・外部編集・IME終了・確認欄の表示失敗では削除を承認しない。
確認中に入力欄を離れた場合は現在の候補を本文に保つが、それによる学習・削除は行わない。

## 候補一覧（Windows）

候補選択中は、読みの先頭付近に最大7件の候補と注釈を表示する。
Space／xで候補を進めると、選択行と表示ページが追従する。送り仮名は各候補に付ける。
PageDown／PageUpでは7候補分ずつ移動する。端では候補を保持し、確定や単語登録を開始しない。
登録欄内で候補を選んでいる間も利用できる。移動だけでは候補を学習しない。
CLIでも `<PageDown>` / `<PageUp>` を使える。
行頭の `1`〜`7` は表示ページ内の選択キー。番号を押すとその候補を確定し、数字自体は本文に入らない。
最終ページなどで該当する行がない場合は、選択を変えずキーを受け止める。
下部の「選択位置 / 総候補数」は全体の通番を示す。CLIも数字キーで7件単位のページから選択できる。
候補を確定して数字の `1`〜`7` を続けたい場合は、先にEnterを押す。
候補選択中以外の数字や `8`・`9`・`0` は従来どおり文字入力として扱う。
英字の暗黙確定も従来どおり。DDSKK標準の `A/S/D/F/J/K/L` 選択は未対応。
候補行の左クリックでも確定できる。登録欄内ではその語だけを欄へ追加し、Enterで登録全体を確定する。
候補ウィンドウはフォーカスを取らず、続くキー入力は元の入力欄へ届く。
見出し・登録中の文字列・操作案内・一覧上下の余白のクリックでは確定せず、背後の本文へクリックを通さない。
押した行から別の行や外へドラッグして離した場合や、押している間に候補ページが変わった場合は選択を取り消す。
クリックの編集は非同期で行い、処理待ちの間の追加入力・取消・入力欄変更・レイアウト破棄で古い要求を無効にする。
アプリの編集を照合できない場合や書き込みを拒否された場合も、古い候補で本文を書き換えない。
Enterで確定、Escape／C-gで読みへ戻ると一覧を閉じる。
フォーカス移動やcompositionの終了でも直ちに一覧を閉じる。

入力アプリがTSFの `BeginUIElement` で独自表示を指定した場合は、自前のウィンドウを出さない。
ホスト独自の表示ページの分け方にかかわらず、PageDown／PageUpの移動量は7候補分とする。
数字キーはホスト指定のページ境界に合わせる。1ページが7件を超える場合は、自前の一覧と同じく
選択行が収まる最大7件を対象とする。UIを提供できない場合はコアの7件単位のページを使う。
TSFから表示位置を取得できない場合も一覧を隠すが、Space／x／Enterによる変換は継続できる。
文書のレイアウト変更後は位置を取り直す。古い入力欄の遅延通知で一覧を再表示しない。
高DPI・画面端の配置処理はあるが、複数ディスプレイや他アプリでの確認は今後行う。

## コアとOSの契約

`would_handle` は読み取り専用。`handle` はキーを消費したかと確定文字列を返す。
Windows側は次状態をコピー上で計算し、文書編集が成功してから採用する。
CLIの `preedit()` は候補マーカー `▽` / `▼` と送り境界 `*` を含める。
Windowsでは `composition_text()` を使い、記号を文書へ挿入せず、読みを点線、
選択中の候補を太い実線のTSF表示属性で示す。実際の描画は入力先アプリに依存する。
未完成のローマ字はそのまま表示する（`Nihon` の途中は「にほn」）。

Windowsでは、矢印・Home/End・PageUp/PageDown・Delete・Tab、通常のCtrlショートカットを
アプリへ渡す前にcompositionの終了を要求する。ただし候補選択中の修飾キーなしPageUp／PageDownは
候補移動として扱う。Shift・Ctrl等を伴うページ操作はアプリへ渡す。`C-j`・`C-g` はSKK操作として処理する。
通常のSKKキー判定は状態を変えないが、この終了処理は `OnTestKeyDown` 内で行い、
キー自体は処理しないと返す。TSF対応RichEditで最初の矢印による移動を確認した。
標準EDITの互換入力経路では、最初の矢印が確定だけになる制限が残る。
即時終了ができないホストでは終了を延期し、次のキーで古い処理を完了させる。
TSFが本文・選択位置を提供する入力欄では、マウス等で選択位置が末尾以外へ移った場合や、
アプリが未確定文字列を変更した場合も終了する。RichEditでクリック・ドラッグ選択・ホスト側の値設定を確認した。
標準EDITの互換経路では、同じ欄へのクリックで未確定表示が移動し、元の位置で終了しない制限が残る。
この終了では現在の本文を保持し、保存していた読みや候補で書き戻さない。
末尾の `n` などの確定処理を行いたい場合は移動前にEnterを使う。

編集通知が遅れた場合に備え、キー処理で上書きする前にも文字列と選択範囲を照合する。
同じ入力欄で次の入力が先に届いた場合は、古いcompositionの終了をその編集セッションで済ませる。
後から届く終了処理は再実行しない。

開発用のダミー推論を有効にすると、送りなし・abbrev以外の未知語／候補枯渇時に非同期要求を送る。
待機中は読みまたは最後の辞書候補を保ち、応答後に生成候補を末尾へ追加する。
追加入力・確定・取消・入力先変更で要求を無効にし、待機中の次のSpaceは通常の登録へ進む。
生成候補の枯渇でも通常登録へ進み、同じ一覧への生成を繰り返さない。
失敗・期限切れでは登録へ戻し、ダミー候補は学習しない。通常は無効。
COMオブジェクトを推論スレッドへ渡さず、入力欄・世代・文脈・期限を確認してからTSF編集セッションで反映する。
詳細は [非同期変換サーバーの検証](INFERENCE.md) を参照。

実モデルは保存設定から有効化する。10文字以上の読みでは初回変換から生成を始め、候補を未操作なら生成候補を先頭へ追加する。
短い読みは辞書を優先し、候補枯渇後に生成する。採点によるpromoteは別設定で有効化し、先頭20件から
第一候補を1.0より大きく上回る最良候補だけを先頭へ移す。残りの候補順と学習方針は保つ。
送りありは語幹と送り仮名を結合して採点する。Space・ページ移動・数字選択等のキー操作と
候補上のマウス押下で保留中の順位変更を無効にする。期限切れなら辞書順を維持する。
生成語は既定では学習せず、明示設定時の短い追加候補だけを保存する。長い生成候補は学習しない。
範囲と設定は [zenz CPUサーバー](ZENZ.md) を参照。
