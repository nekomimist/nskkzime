## 構成

- `include/nskkzime/`, `src/core/`: OS非依存の入力状態と辞書インターフェース。
- `src/windows/`: TSF、COM、入力欄のcomposition、キーの変換、辞書設定と非同期学習IPC。
- `src/tools/`: コアの操作を再現するCLI、設定CLI／GUI、辞書補助プロセスと実入力検証アプリ。
- `tests/`: コアの回帰テストと、TSFのCOM契約・編集処理を検証するホスト。
- `src/dictionary/`: SKK辞書の読み込みと検索、ユーザー辞書の順位と保存形式。
- `src/server/`: 変換・採点のプロトコルと、skk-zenz / llama.cppのCPU推論バックエンド。

`runtime_configuration` は入力サービスの初期化時に設定と環境変数を取得し、辞書・ローマ字・
推論・候補表示・GUIの保存先へ同じ値を渡す。辞書の共有はこの設定の所有権と分ける。
broker経由では、辞書と設定をひとつの不変スナップショットとして公開する。
`broker_snapshot` はデスクトップと同じ辞書・ローマ字の読み込み処理を使い、部分失敗の診断と
学習の可否を応答に含める。初期取得ごとに元データを読み、内容ハッシュによる既存辞書キャッシュを利用する。

`text_service` はTSF通知と入力の進行を担当する。編集セッションと範囲操作は `tsf_edit`、
本文への反映とcompositionの寿命は `composition_session`、推論の待機状態・要求識別・取消は
`inference_session` に分ける。ホスト呼び出し後の状態照合、入力属性の確認、UIの更新順はTSF側で維持する。

コアはイベントから未確定文字列・確定文字列を生成する。候補にはID、表記、注釈、出所、
学習方針を持たせる。辞書は起動時にファイルから読み込む不変のメモリースナップショット。
キー処理内の検索ではファイルへアクセスしない。学習は別プロセスで保存し、スナップショットを差し替える。
`Engine::revision()` は消費したイベント・候補追加またはresetで進む。非同期結果検証には
これに加えて入力欄セッションID・要求ID・文脈世代を使う。

TSFは編集が成功するまでコアの次状態を採用しない。通常のSKKキー判定では状態を変えない。
矢印やアプリのショートカットを渡す前には、判定通知内でcompositionの終了だけを要求する。
これは実入力で確認したホストのキー配送に合わせた例外で、重複通知でも一度だけ終了する。
標準EDIT等がtransitory extensionの親文書を公開する場合は、親の本文・選択・編集通知を使う。
親がない場合は元のcontextを使用し、入力属性・読み取り専用判定は編集先でも維持する。
推論はIME DLLへリンクせず、停止しても辞書入力を継続できる構造にする。

## Phase 5: 非同期推論との接続（v0.2）

順序は、辞書候補枯渇後の生成 → 長い読みの生成優先 → 辞書候補の並べ替え。
最初の設定値はskk-zenzを参考に、長い読み10文字以上、前後文脈各40文字、生成候補5個。
`promote` 方式を先に実装し、辞書の順位を保ちやすくする。
辞書候補枯渇後の候補追加、入力欄・世代・文脈・期限の照合、取消・確定・入力先移動時の無効化、
通常登録への復帰を実装済み。保存設定から実モデルへの起動・共有・復旧をDLL経由で検証した。
長い読みの生成優先と、候補採点によるpromoteも実モデル／DLL経由で確認した。
生成候補は既定では学習禁止。設定で短い追加生成語の学習を有効化できる。長い生成候補は常に学習禁止。
登録できない設定では、失敗時も読みを保って入力を継続する。
登録版のプローブ画面でもRichEditの文脈付き採点・確定、標準EDITの長い読みの生成・確定を確認した。
実モデルの外部アプリでの検証は残る。

- [x] 応答適用時に要求ID・入力欄・状態世代・文脈を照合する。
- [x] 確定、取消、追加入力、フォーカス変更で古い要求を無効化する。
- [x] 候補一覧のキー操作・マウス押下から、選択候補や番号を並べ替えない。
- [x] 時間切れで辞書へ切り替えた要求の遅延応答は捨てる。
- [x] 文脈を取れない入力欄では文脈なしで動く。
- [x] 送りありは語幹＋送り仮名を採点。送りありの生成は後回し。
- [x] 長い生成候補は自動学習せず、短い追加候補は設定に従って学習する。
- [x] パスワード等の入力では推論・文脈取得・学習をしない。
- [x] 本文や読みを保存するログは明示設定でのみ有効にする。既定オフ、GUI／CLIの切替、
  応答時と反映後の入力属性照合、作業スレッドでの保存、容量上限と失敗時の変換継続を実装。
  保護入力・古い応答・途中取消を隔離テストで確認。範囲と利用手順は [診断用入力ログ](DIAGNOSTICS.md)。

完了条件: 推論中の連打・取消・アプリ切替・サーバー停止でも、古い結果が入力欄へ混入しないこと。
