# 実装計画

更新: 2026-10-04。Windows / x64を最初の対象とする。
第一段階は辞書だけで日常利用できるSKK、第二段階は `nkkz-ime-server` によるzenz連携。
サーバー名は当初の提案どおり。リポジトリ・コア・IME名は `nskkzime` とする。

## 構成

- `include/nskkzime/`, `src/core/`: OS非依存の入力状態と辞書インターフェース。
- `src/windows/`: TSF、COM、入力欄のcomposition、キーの変換。
- `src/tools/`: コアの操作を再現するCLI。
- `tests/`: コアの回帰テストと、TSFのCOM契約・編集処理を検証するホスト。
- `src/dictionary/`: SKK辞書の読み込みと検索。ユーザー辞書の永続化は今後追加。
- 将来の `src/server/`: skk-zenzのC++推論コードを再利用した別プロセス。

コアはイベントから未確定文字列・確定文字列を生成する。候補にはID、表記、注釈、出所、
学習方針を持たせる。辞書は起動時にファイルから読み込む不変のメモリースナップショット。
キー処理内の検索ではファイルへアクセスしない。現在は読み取り専用である。
`Engine::revision()` は消費したイベントまたはresetで進む。将来の非同期結果検証には
これに加えて入力欄セッションID・要求ID・文脈世代を使う。

TSFは編集が成功するまでコアの次状態を採用しない。キー判定では状態を変えない。
推論はIME DLLへリンクせず、停止しても辞書入力を継続できる構造にする。

## Phase 5: 非同期推論との接続（v0.2）

順序は、辞書候補枯渇後の生成 → 長い読みの生成優先 → 辞書候補の並べ替え。
最初の設定値はskk-zenzを参考に、長い読み10文字以上、前後文脈各40文字、生成候補5個。
`promote` 方式を先に実装し、辞書の順位を保ちやすくする。

- 応答適用時に要求ID・入力欄・状態世代・文脈を照合する。
- 確定、取消、追加入力、フォーカス変更で古い要求を無効化する。
- 候補一覧を操作し始めてから、選択候補や番号を並べ替えない。
- 時間切れで辞書へ切り替えた要求の遅延応答は捨てる。
- 文脈を取れない入力欄では文脈なしで動く。
- 送りありは語幹＋送り仮名を採点。送りありの生成は後回し。
- 長い生成候補は自動学習せず、短い追加候補は設定に従って学習する。
- パスワード等の入力では推論・文脈取得・学習をしない。
- 本文や読みを保存するログは明示設定で有効にする。

完了条件: 推論中の連打・取消・アプリ切替・サーバー停止でも、古い結果が入力欄へ混入しないこと。

## Phase 6: 品質・配布

- 既存評価コードを基に、上位候補正解率、並べ替え改善／悪化、操作回数を評価する。
- キー処理、辞書、生成、採点のp50/p95を別々に測る。
- 初期目標: ウォーム状態のキー処理p95 5ms以内、辞書候補提示20ms以内。未実測。
- 生成1秒・採点0.3秒を期限の出発点として実測後に調整する。
- クリーン環境への導入・更新・復旧、必要なライセンス表示、署名、CPU要件。
- GPU対応や入力中の先読みはCPU版の評価後に検討する。
