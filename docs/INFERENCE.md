# 非同期変換サーバーの検証

`nkkz-ime-server.exe` は通常ビルドではダミー応答、`-Zenz` ビルドではllama.cppによる実変換・採点に対応する。
IME側は既定で無効。保存設定でzenzを有効にすると、長い読み・辞書候補の枯渇時に実モデルへ要求する。
辞書候補の採点によるpromoteも設定で有効にできる。長い読みの初期値は10文字、採点は既定でオフ。
ビルド・モデル取得・設定・計測は [zenz CPUサーバー](ZENZ.md) を参照。

## 試し方

初回のIME登録後、ビルド先の `ime_probe_async.exe` を起動して「nskkzimeを選ぶ」を押す。
このアプリは専用の小辞書、ビルド先DLL、`probe-async-user-dictionary.nskkdb` を使う。
日常のユーザー辞書は変更しない。Ctrl+jでひらがなへ切り替え、`Mikan` → Spaceと入力すると、
約8秒後に「試験〈みかん〉」「別候補〈みかん〉」を表示する。8秒は取消操作を確認するための検証用設定。
Enter・数字・クリックで確定でき、生成したダミー候補は学習しない。

- 辞書候補のない読み、またはSpaceで辞書候補を使い切った場合に要求する。
- 送りあり・abbrev・登録欄内は要求しない。
- 辞書候補は元の順序を維持して生成候補を末尾へ追加し、最初の追加候補を選ぶ。
- 生成候補を使い切ったら通常の単語登録へ進む。同じ一覧への生成を繰り返さない。
- 待機中も入力・確定・取消ができる。Spaceをもう一度押すと待機を取り消して通常の単語登録へ進む。
- 応答なし・異常応答・期限切れでは通常の登録へ戻す。登録UIを表示できない場合は読みを維持する。
- 入力の変更、確定、取消、フォーカス移動、IMEの解除、文脈の変化で古い応答を無効にする。

検証アプリには要求待ち・反映・破棄・期限切れの状態を表示する。
文脈確認のチェックは画面上の表示だけを制御する。推論が有効なら、要求時にはチェックと独立して
前後各40 Unicode文字を取得する。変換対象は含めない。保護・属性不明の入力欄では送信しない。
通常属性を確認できても周辺範囲を安全に取得できない場合は、前後を空にして要求する。
本文・読み・候補のログは保存しない。

## 構成と期限

IMEのキー処理は要求をメモリーへ置くだけで、接続・サーバー起動・I/Oを待たない。
バックグラウンドワーカーが名前付きパイプを使う。待機要求は最新1件へ置き換え、古いI/Oを取り消す。
COMオブジェクトや入力欄のウィンドウはワーカーへ渡さない。
UIスレッドのディスパッチャーが完了を受け取り、非同期のTSF編集セッションを要求する。

編集を実行するときに、要求ID・入力コアのrevision・compositionセッション・文脈世代・
入力欄とcompositionの同一性・実際の文字列とキャレット・入力属性・前後文脈・期限を照合する。
応答を受け取った時点では有効でも、編集ロックの取得待ちで期限が過ぎた結果は採用しない。
編集成功後だけコアの新状態と候補UIを採用する。

接続から応答まで同じ絶対期限を使う。通常の検証設定は1秒、専用プローブは10秒。
取消や期限切れでは `CancelIoEx` の後にI/O完了を回収し、`OVERLAPPED` とバッファーの寿命を守る。
TSFの解除はワーカー終了を待たず、DLLはワーカーの完了まで参照を保持する。
サーバーは4接続まで並行して受け付け、無通信で既定10秒後に終了する。zenzのモデル計算は1要求ずつ行う。
無通信の確認中も接続受付は維持する。定期確認のたびに受付を取り消すと、同時に成立した接続を
切断する競合が起きうるため、取消はサーバーが実際に無通信で終了するときだけ行う。
終了時に接続成立が先行していた場合はその接続を処理する。

## 名前付きパイプとプロトコル

パイプ名は `\\.\pipe\nkkz-ime-v1-<ユーザーSID>-<token>`。
トークンは1〜64文字の英数字・ハイフンに限定する。ACLは現在のユーザーだけを許可し、
リモート接続を拒否する。双方がパイプの相手プロセスのユーザーSIDを照合してから本文を送る。
クライアントは匿名のSQOSを指定し、サーバーによるクライアント権限の偽装を許可しない。
最初のパイプインスタンスには `FILE_FLAG_FIRST_PIPE_INSTANCE` を指定する。
この仕組みは同一ユーザーの悪意あるプロセスとの隔離を保証するものではない。

1接続でhello → convert/score要求 → 応答の順にUTF-8 JSON Linesを1行ずつ交換し、クライアントが閉じる。
skk-zenzのprotocol 2のフィールドを参考にしたが、現段階では互換サーバーではない。
必須フィールド・hello名・接続寿命・上限は以下の検証用契約に従う。

```json
{"hello":"nkkz-ime-server","protocol":2,"backend":"dummy","version":"0.0.1"}
{"id":1,"op":"convert","kana":"みかん","left":"前","right":"後","n":5}
{"id":1,"candidates":["試験〈みかん〉","別候補〈みかん〉"],"scores":[0.0,0.0]}
```

行の上限は改行を除き16 KiB、JSONの入れ子は8段まで。キー重複・不正UTF-8・不正型を拒否する。
IDは正の64bit整数、要求候補数は1〜8、読み・候補は1024 Unicode文字以下、文脈は片側40文字以下。
候補の空文字・制御文字・埋め込みオブジェクト文字を拒否し、応答IDと要求候補数上限を照合する。
ダミーの `scores` は0。実モデルでは有限の実スコアを返し、候補数との一致も照合する。
`score` は入力順のスコア配列を返す。採点候補は0〜64個で、空文字も受け付ける。
IMEは生成に `convert`、候補のpromoteに `score` を使う。送りありの採点では読み・候補とも送り仮名を含める。
標準入出力モードはhelloの後で複数要求を処理し、不正行を本文なしのerror応答にして継続する。
JSON処理には同梱の [nlohmann/json 3.12.0](../third_party/README.md) を使う。

## 開発用設定

ダミー検証の設定はプロセス環境変数で明示する。実モデルの永続設定は [ZENZ.md](ZENZ.md) を参照。

| 環境変数 | 既定値 | 意味 |
|---|---|---|
| `NSKKZIME_INFERENCE_DUMMY` | 保存設定 | `1` はダミー推論、`0` は保存設定も含め推論を無効化 |
| `NSKKZIME_INFERENCE_TOKEN` | ダミーはランダムID、zenzは設定のハッシュ | 開発用の接続先トークン |
| `NSKKZIME_INFERENCE_DELAY_MS` | 150 | ダミーサーバーの応答遅延。0〜10000 |
| `NSKKZIME_INFERENCE_TIMEOUT_MS` | 保存設定または1000 | 要求期限。1〜10000 |

ダミーではサーバーがいなければDLLと同じ場所の `nkkz-ime-server.exe` を明示パス・非表示で起動する。
zenzでは保存されたサーバーとモデルの絶対パスを使う。同じ設定のアプリは接続先を共有し、
同時起動では同一ユーザー限定の名前付きイベントを確保した1プロセスだけがモデルを読み込む。
モデル・サーバーのパス、スレッド数、期限が異なる場合は接続先を分ける。
プローブは遅延8000ms・期限10000msを設定する。サーバーを単独起動する場合の例:

```powershell
.\out\build\windows-x64\Release\nkkz-ime-server.exe --dummy --pipe-token local-test --delay-ms 150 --idle-ms 10000
```

通常のデスクトップx64プロセスで検証している。AppContainer・低整合性・昇格プロセス間の接続、
ブラウザ等での互換性は未確認。属性を提供しない入力欄では推論を見送り、通常の辞書変換を継続する。

参照: [skk-zenzのprotocol 2](https://github.com/nekomimist/skk-zenz/blob/db1c923223a94c6406fd19e4d75ef3b54bdf9300/src/protocol.cpp)、
[CancelIoExの完了条件](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex)。
