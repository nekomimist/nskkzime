# 使い方と仕様

DDSKKの操作を基にした現在の仕様。DDSKKとの違いは「DDSKKとの違い」を参照。

## 設定

設定は `%LOCALAPPDATA%\nskkzime\settings.ini`（UTF-8）。入力モード「あ／ア／A」の右クリックメニューの
「設定…」か `nskkzime_settings.exe` で編集する。どちらも保存前に辞書・ルールを読み込んで検査する。
変更は利用するアプリを起動し直すと反映される。

```powershell
nskkzime_config.exe --set-dictionaries 'C:\辞書\personal.skk' 'C:\辞書\SKK-JISYO.L'
nskkzime_config.exe --set-zenz 'C:\models\ggml-model-Q5_K_M.gguf'
nskkzime_config.exe --show
nskkzime_config.exe --check
```

| キー | 既定値 | 内容 |
|---|---|---|
| `dictionary` | なし | 読み取り専用のSKK辞書の絶対パス。複数行で、先に書いた辞書を優先（最大32） |
| `learning` | on | 確定した候補の学習と単語登録 |
| `romaji` | なし | 独自のローマ字ルールファイル |
| `candidate-show-after` | 1 | 候補一覧を表示するまでのSpace回数（1〜99） |
| `candidate-keys` | numbers | 一覧の選択キー。`numbers`（1〜7）か `asdfjkl` |
| `inference` | off | `zenz` で推論を有効化 |
| `zenz-model` | なし | GGUFモデルの絶対パス |
| `zenz-server` | なし | 開発用。省略時はIMEと同じ版のサーバー |
| `inference-threads` | 4 | 推論スレッド数（1〜64） |
| `inference-timeout-ms` | 1000 | 生成の期限 |
| `zenz-idle-seconds` | 1800 | サーバーが要求なしでモデルを保持する時間（1〜86400） |
| `zenz-min-length` | 10 | この文字数以上の読みは生成を優先（0で無効） |
| `zenz-rerank` | off | 辞書候補を採点して最良の候補を先頭へ移す |
| `zenz-rerank-wait-ms` | 100 | 最初の候補を表示する前に採点を待つ上限（0で待たない） |
| `zenz-rerank-limit` | 20 | 採点する候補数（2〜64） |
| `zenz-score-timeout-ms` | 300 | 非同期の採点の期限 |
| `zenz-promote-threshold` | 1.0 | 先頭へ移すのに必要なスコア差 |
| `zenz-max-score-gap` | 8.0 | 生成候補を残す最大のスコア差 |
| `zenz-learn-fallback` | off | 短い（9文字以下）追加生成語の学習 |
| `zenz-unknown-context` | off | 入力属性の分からない欄でも前後の本文をzenzに渡す |
| `input-log` / `input-log-directory` | off | 診断用の入力ログ（下記） |
| `tsf-log` / `tsf-log-directory` | off | 本文・打鍵内容を含まないTSF診断ログ（下記） |

設定ファイルがない場合は内蔵のテスト用辞書（5見出し）で動き、設定が壊れている場合はかな入力だけになる。
複数の辞書の一部が読めない場合は、読めた辞書を使い、学習は止める。

## キー操作

| 入力・状態 | 動作 |
|---|---|
| 小文字 | ローマ字かなを入力。未完成のローマ字だけを保持 |
| 大文字 | 読みの入力を開始。読みがあれば送り仮名を開始 |
| 読み入力中のSpace | 変換。末尾の `n` は「ん」にする |
| 候補選択中のSpace／`x` | 次／前の候補。最後の候補の次は単語登録、先頭の前は読みに戻る |
| 候補選択中の `1`〜`7`（または `asdfjkl`） | 表示ページの候補を確定 |
| 候補選択中のPageDown／PageUp | 7候補ずつ移動 |
| 候補選択中の `X` | 学習語の削除確認。`yes`＋Enterで削除 |
| 候補選択中の通常の文字 | 候補を確定し、その文字の入力を続ける |
| Enter | 候補または読みを確定（改行はアプリへ渡さない） |
| C-g／Escape | 候補から読みへ、読みなら取り消し |
| Backspace | 候補から読みへ戻る、または未完成ローマ字・読み・送りを1文字消す |
| `q` | かな⇔カナの切り替え。読みの入力中は反対のかな種で確定 |
| `l` | 英数（Latin）へ |
| `/` | abbrev（英字見出し）を開始 |
| 通常のかな入力中の `Q` | 読みを開始。数字から始まる見出しも入力できる |
| C-j | 確定してひらがなへ |
| 半角／全角、Ctrl+Space | IMEのオン／オフ。IMEオン／オフキーにも対応 |

- 撥音は `n`＋子音、`n'`、末尾の `n`、`nn`。`nn` の2つ目の `n` は次の音節に使う（`konnichiha` →「こんにちは」）。
- `z` → Spaceは全角空白、`zh/zj/zk/zl` は矢印、`z.` `z,` `z/` `z[` `z]` は記号。
- Shiftを離すのが遅れても、最初のかなと送り仮名の途中は1つの入力として扱う
  （`KAnji` = `Kanji`、`KaKU` = `KaKu`、`KOroNde` = `KoroNde`）。
- 矢印・Home/End・Delete・Tab・Ctrlショートカットではcompositionを終了してからアプリへ渡す。
  本文はそのまま残し、学習はしない。フォーカスの移動やクリックで選択位置が変わった場合も同じ。

## 送り仮名とabbrev

送りありの変換は「語幹の読み＋送り開始の英字」で検索し、入力した送り仮名の候補ブロックを優先する
（`おおk /大/多/[く/多/]/[き/大/]/` では `OoKu` →「多く」、`OoKi` →「大き」）。

`/` の後は英字・数字・記号をそのまま見出しにして、大小文字を区別して検索する。
読みの入力中は `q` `l` `x` も文字として扱い、大文字で送り仮名を始めない。
Enterで英字のまま確定する。確定・取り消しの後は開始前のかなモードへ戻る。

## 数値変換

`/99` の後にSpaceを押すと、辞書にある `#` の見出しから数値候補を作る。
`Q99en` →「九十九円」、`Dai12kai` →「第十二回」のようなかなを含む見出しにも使える。
候補の並びは辞書と学習による。例えば `# /#1/#3/#2/` なら「９９」「九十九」「九九」の順になる。

| 辞書候補の指定 | 例 |
|---|---|
| `#0` | `99` →「99」 |
| `#1` | `99` →「９９」 |
| `#2` | `99` →「九九」、`0009` →「〇〇〇九」 |
| `#3` | `99` →「九十九」、`0009` →「九」、`0` →「〇」 |
| `#8` | `1234567` →「1,234,567」（先頭ゼロは除く） |

連続する数字を1つの `#` に置き換えて検索し、候補の指定へ左から順に数字を渡す。
例えば `#m#d /#0月#0日/` があれば `/2m25d` →「2月25日」となる。
全角数字は半角へ、数字間のカンマは除いて検索する。小数点や符号は見出しの文字として残す。
`/2.25` は `#.#` の見出しで検索するので、日付などの候補を登録できる。

ユーザー辞書、設定した辞書の順を保ち、各辞書では完全一致の見出しを数値見出しより優先する。
「九九」を選ぶと `# /#2/` を学習し、別の数字でも同じ形式を優先する。
`X` でその学習を削除すると辞書の元の順位に戻る。候補の表示が同じなら先にある指定を採用する。
通常の単語登録は入力した見出しへの具体的な語として保存し、表記から数値指定を推測しない。
数値テンプレートはSKK辞書ファイルから読み込み・インポートできる。

`#3` は20桁（京の位まで）、展開結果は1024文字まで。
未対応の `#4`（再検索）、`#5`（大字）、`#9`（将棋）、不正な指定や数字不足は数値候補から省く。
数字を含まない入力では `#2` などを文字どおり扱う。

## 単語登録

辞書に候補がない読み、または最後の候補からさらにSpaceを押した読みで登録を始める。
本文には元の読みを残し、キャレット付近の別欄で登録する語を入力する。欄の中でも通常のSKK操作が使える。

- Enterで登録欄全体を確定し、読みを登録した語に置き換える。
- 空のままEnter、または変換中でないEscape／C-gで取り消して読みに戻る。
- 欄の中でさらに未知語を変換すると再帰登録になる（8段、各1024文字まで）。
- 送りありの登録では語幹だけを入力する。
- フォーカスの移動などでcompositionが終わると、登録途中の内容は捨てて読みを残す。

## 学習と削除

確定した候補はユーザー辞書の先頭に保存され、次の変換と他のアプリに反映される。
学習は読み・送りキー・送り仮名ごと（「書く」の学習は「書け」に影響しない）。
生成候補は既定では学習しない。長い読みの生成候補は常に学習しない。

候補選択中の `X` で確認欄を開き、`yes`＋Enterでその語の学習を削除して読みに戻る。
送り別の登録を優先し、なければ共通の候補を対象にする。読み取り専用辞書の同じ語は候補に残る。
パスワード・private・PINの欄では学習・登録・削除をしない。

## 候補一覧

候補選択中は読みの近くに7件ずつ、注釈とともに表示する。行のクリックでも確定でき、
一覧はフォーカスを取らない。`candidate-show-after` を2以上にすると、その回数のSpaceまで
本文内だけで候補を切り替える（PageDown／PageUpは直ちに一覧を開く）。
アプリが `ITfUIElement` で独自の候補表示を指定した場合は、自前の一覧を出さない。

## zenz

`--set-zenz` か設定GUIの「推論」でモデルを指定すると有効になる。推論サーバーは同梱版を使う。
モデルは `scripts/prepare-zenz.ps1` で取得する zenz-v3.2-small（`ggml-model-Q5_K_M.gguf`）を想定している。

- 辞書に候補がない読みと候補を使い切った読みでは、生成した候補を一覧の末尾に追加する。
- 10文字以上の読みでは、最初の変換から生成した候補を先頭に追加する。
- `zenz-rerank=on` では辞書候補を前後の文脈で採点し、最良の候補を先頭へ移す。
  最初の表示の前に最大 `zenz-rerank-wait-ms` 待つため、通常は表示後に順位が変わらない。
- 送りありは語幹＋送り仮名で採点する。送りありの生成はしない。
- サーバーの起動失敗・期限切れでは辞書の候補で続ける。

## ローマ字ルール

UTF-8のタブ区切りファイルで内蔵ルールに追加・上書きできる（[サンプル](../examples/romaji.tsv)）。

```text
version=1
wi<TAB>ゐ
jj<TAB>っ<TAB>j
nn<TAB>ん
```

列は「入力・出力・次に残す入力（省略可）」。入力は1〜16文字の小文字ASCIIで、`q` `l` `/` 空白で始まるものは使えない。
既存ルールへ到達できなくなる定義や重複は拒否し、不正な行が1つでもあればファイル全体を使わない。
DDSKKと同じ `nn` の動作（2文字で「ん」）にしたい場合は `nn<TAB>ん` を追加する。

## 辞書の形式

- 文字コード: UTF-8、EUC-JP（SS2半角カナ、SS3のJIS X 0212補助漢字を含む）。BOM、先頭行の `coding:`、内容の順で判別。
- 送りあり／送りなしのセクション、注釈（`;`）、送り仮名ブロック（`[く/…/]`）、引用文字列だけの `concat` に対応。
- 数値変換は `#0` `#1` `#2` `#3` `#8` に対応。Lisp式は実行しない。関数による動的候補は未対応。
- 壊れた行は行単位で飛ばし、件数と行番号を設定の検査結果に表示する。辞書全体は128 MiBまで。

## ユーザー辞書の管理

```powershell
nskkzime_user_dictionary.exe --list
nskkzime_user_dictionary.exe --forget 'か' '描' --okuri k 'く'
nskkzime_user_dictionary.exe --export 'C:\辞書\nskkzime-export.skk'
nskkzime_user_dictionary.exe --check-import 'C:\辞書\my-skk-jisyo'
nskkzime_user_dictionary.exe --import 'C:\辞書\my-skk-jisyo'
```

入力モードメニューの「学習辞書の管理…」（`nskkzime_dictionary_gui.exe`）でも、一覧・絞り込み・削除・
取り込み・書き出しができる。取り込みは既存の順位を保ち、不正な行があれば全体を拒否する。
書き出したファイルはSKK形式で、通常の読み取り専用辞書としても使える。

## 入力ログ

変換の調査用に、設定GUIの「診断」か `--enable-input-log <フォルダー>` で有効にできる。
推論の読み・前後各40文字の本文・候補・スコアを、指定したローカルフォルダーへ平文のJSON Linesで保存する。
入力属性が確認できた通常の欄だけを記録し、1ファイル1 MiB・64ファイルで停止する。古いログは自動削除しない。

## TSF診断ログ

アプリによる入力の違いや、未確定入力が途切れる不具合を調べるためのログ。
更新したIMEを導入したあと、設定GUIの「診断」で「TSF診断ログ」をオンにし、
作成済みのローカルフォルダーを指定する。CLIでも設定できる。

```powershell
nskkzime_config.exe --enable-tsf-log 'C:\temp\nskkzime-tsf'
nskkzime_config.exe --disable-tsf-log
```

保存後は対象アプリを終了して起動し直す。推論のオン・オフとは独立して動作し、既定はオフ。
現在は通常のデスクトップアプリに対応する。AppContainerアプリでは保存未対応と表示する。

`nskkzime-tsf-*.jsonl` に通知の順序、未確定入力の終了理由、APIの成否、
入力モード・段階、ローマ字や読みの長さを記録する。アプリの実行ファイル名、PID、TIDも含む。
本文・読みの内容・キー内容・ウィンドウのタイトル・ファイルのパスは記録しない。
入力先や未確定入力の番号は、そのログ内だけで使うインターフェースポインターの識別子。
COMの同一性を保証する番号ではなく、保持数の上限やポインターの再利用にも注意する。

各ログ種類について1ファイル1 MiB・同じフォルダーに64ファイルまでで停止し、既存ファイルは削除しない。
キー処理でファイルを書かず、512件までのキューから別スレッドで保存する。
混雑時には記録を捨て、`seq` の飛びと `dropped` の累計で欠落を示す。
検証アプリの状態欄には、そのプロセスの保存状態・上限・保存失敗・欠落数を表示する。

未確定入力が途切れた場合は `finish_composition` / `engine_reset` の直前を見る。
`range_read_failed` や `selection_unavailable` は取得失敗、`text_mismatch` / `caret_mismatch` は照合不一致、
`host_termination` はアプリ側からの終了通知。`invalid_after_edit` は編集通知での照合から終了したことを示す。
`engine_reset` の `detail` は0がリセット前、1がリセット後。
`edit_request` の完了記録は `hr` が要求自体の結果、`detail` が編集セッションの結果、`detail2` が要求フラグ。
`call` / `parent_call` / `depth` / `phase` で同じログ内の処理の入れ子を、`request` で非同期の編集要求と実行を対応付ける。
`result_known=false` の `hr` は結果がまだない記録で、成否の判定には使わない。
`state_source=request` は要求時点の状態。実行時に状態を更新できた記録は `current` になる。
API診断は元の呼び出しの結果を記録し、ログのために本文や選択位置を再取得しない。

`document_focus` のpoint記録の `detail` / `detail2` は新旧documentの番号。
`document_top` は `hr` がGetTopの結果、`detail` が未解決のtop、`detail2` がdocumentの番号。
`focus_resolved` の `context=0` は入力先を解決できなかったことを示す。
その場合は終了判断を非同期に保留し、同じ入力先への復帰か、その入力先での正常なキー処理で取り消す。
復帰やキー処理が非同期判断より先に来なければ未確定入力を終了する。別の入力先への移動や明確な離脱では即時に状態を破棄する。
`focus_deferred` の `detail` は予約番号、`detail2` は0が予約・1が終了判断・2が予約失敗・3が無効な予約の破棄。
`focus_cancelled` は取り消しの理由を記録する。

## DDSKKとの違い

| 操作 | DDSKK | nskkzime |
|---|---|---|
| `Kanji SPC RET` | 確定して改行 | 確定のみ。次のEnterをアプリへ渡す |
| `Kanji SPC BS` | 「漢」を確定 | 読みに戻る |
| `ky BS a` | 「あ」 | 未完成ローマ字を1文字ずつ消すので「か」 |
| `hannou` | 「はんおう」 | 「はんのう」（ルールで変更可） |
| `Kanji SPC 2` | 「漢字2」 | 2番目の候補を確定 |
| 候補一覧での選択 | 5回目以降のSpaceで一覧、`asdfjkl` | 最初から一覧、`1`〜`7`（設定で変更可） |
| `fka` | 「か」 | 不成立のローマ字を残し「fか」 |
| `X yes RET` | 入力全体を消す | 削除後に読みへ戻る |

未対応: 読みの途中での `Q` による変換開始位置の変更、`L` の全英、半角カナ、数値変換の `#4` `#5` `#9`、接頭辞・接尾辞、補完、再変換、
AZIK、`ArukU` などShiftの位置ずれの補正、Lispによる設定。
