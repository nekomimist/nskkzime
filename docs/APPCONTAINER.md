# AppContainerからの入力

Windows検索とMicrosoft Storeは、この端末では実際にAppContainerのトークンで動作する。
Windows Terminalのimmersive/XAML互換性登録だけでは、私用辞書やデスクトップ用IPCにアクセスできない。

## 構成

`nskkzime_broker.exe` は本人の通常権限のデスクトッププロセスとして常駐する。
インストーラーはHKCUのRunに起動を登録し、更新時はExplorer経由で `--replace` を実行する。
本人・セッション単位のmutexで多重起動を防ぎ、`--stop` で終了する。
モデルのロード・待機終了は従来どおり `nkkz-ime-server.exe` が担当する。

許可するパッケージは次の2つに限定する。

- `MicrosoftWindows.Client.CBS_cw5n1h2txyewy`（Windows検索）
- `Microsoft.WindowsStore_8wekyb3d8bbwe`（Microsoft Store）

IMEは最初に設定、ローマ字規則、コンパイル済み辞書イメージを非同期取得する。
かな入力とキー処理は取得・推論の完了を待たない。学習とzenz要求もワーカー経由で中継する。
表示回数・ASDFJKL・文脈利用等の既存設定をそのまま適用する。
AppContainerから設定GUI・辞書管理GUIを起動する機能は提供しない。

辞書とローマ字規則はデスクトップと共通の読み込み処理を使う。
一部の辞書が失敗しても、読み込めた辞書を設定順で使い、診断を表示する。この場合は学習・単語登録を停止する。
独自ローマ字規則の失敗では内蔵規則で継続し、辞書が正常なら学習も継続する。
初期取得ごとに元ファイルを読み、辞書の内容ハッシュによる共有・永続キャッシュを利用する。
サイズと更新日時を保った差し替えも検出し、元ファイルがない場合は古いキャッシュへ戻さない。

現行の初期取得は `INI2` を使い、CBOR version 2の応答に診断と学習の可否を含める。
旧クライアントの `INIT` には従来のversion 1の7項目を返す。
旧クライアントは部分失敗時の学習停止を表現できないため、辞書・独自ルールがすべて正常な場合にだけ応答する。

パッケージ化された通常権限アプリと、設定ファイルの実体が仮想化されている子プロセスも
同じbrokerからデータを取得する。後者にはパッケージIDのないプロセスもあるため、
既定設定を開いたハンドルの実パスを照合する。明示した開発用設定・辞書はこの切替の対象外。
通常権限の専用パイプは本人・同一セッション・非AppContainerのクライアントだけを受け付ける。
この経路からの設定／辞書GUI起動は、brokerが決定した同梱EXEと共有設定パスに限定する。
アプリ専用の古い設定コピーは削除・同期せず、IMEは通常デスクトップ側の設定を利用する。

## 接続とデータの境界

- Program Filesの公開プログラムだけをALL APPLICATION PACKAGESに読み取り・実行許可する。
  書き込みはSYSTEMとAdministratorsのみ。設定・辞書・学習・モデル・入力ログのファイルACLは変更しない。
- パイプはコンテナーSIDとWindowsセッションごとの名前空間に作成し、
  本人SIDと許可したコンテナーSIDにだけ通信権限を与える。コンテナーにpipe instance作成権は渡さない。
- サーバーはクライアントの実プロセストークンからユーザー・セッション・コンテナーSIDを照合する。
  クライアントも同一ユーザー・セッションと、IME DLLと同じフォルダーのbroker実行ファイルを確認する。
  このためbrokerのプロセスとトークンには、許可したSID向けの照会権だけを追加する。
- 通信は長さ上限、期限、取消付き。任意ファイルパス・コマンド・辞書インポートの要求は受け付けない。
  候補学習／削除・スナップショット・推論・明示有効化された入力ログと、上記の固定GUI起動だけを中継する。
- 設定の内容ハッシュを要求に付ける。ワーカーは作成時のハッシュを保持し、設定変更後の古い要求は拒否する。
  設定と辞書は同じスナップショットから一度に公開し、入力サービスは自身の辞書に結び付いた設定を使う。
  推論・学習・GUI起動もその世代を保持し、別の初期化の設定を参照しない。
- パスワード等への推論・学習抑止、属性不明でのログ抑止は従来のTSF判定を通す。
  入力ログはアプリ側で現在の文脈と属性を再検証した後だけ要求する。

デスクトップ側がコンテナーの名前空間にオブジェクトを作る方式については、
[Microsoftの名前付きオブジェクト共有資料](https://learn.microsoft.com/en-us/windows/apps/develop/communication/sharing-named-objects)を参照。
私用ファイルを全AppContainerへ公開したり、ネットワークのloopback exemptionを追加したりしない。

## テストと制約

### 永続診断ログ

brokerは既定で `%LOCALAPPDATA%\nskkzime\diagnostics\broker.jsonl` に診断を記録する。
`--config` を明示した検証用brokerでは、その設定ファイルの親の `diagnostics` を使う。
通常の入力ログの有効・無効とは独立して動作し、設定ファイルの変更は不要。
各行にはUTC時刻、PID・TID、Windowsセッション、接続先のコンテナーSID、固定のイベント名と処理段階、
失敗理由、取得できた場合だけWin32コード、要求元PID、所要時間を含む。
入力本文、読み、候補、要求・応答、設定内容、辞書・モデルのパス、例外メッセージは記録しない。
起動時のbroker実行パスは、配置版を識別するため記録する。

- `broker_start`／`broker_failed`／`broker_exit`：起動、失敗、終了。起動時の全接続口作成も記録する。
- `endpoint_state`：broker側から完全名を5秒ごとに照会する。
  `available`、通常の混雑を示す `busy`、名前が見つからない `missing`、その他の `error` を区別し、
  状態変化時と60秒ごとに記録する。予定4本に対する稼働listener数と処理段階も含む。
- `bootstrap_received` → `snapshot_ready` → `bootstrap_response_acked`：
  初回取得の受信、元辞書の読み込み成功・失敗件数と内蔵ローマ字への退避、応答ACKまでを記録する。
  ACKの後にクライアントが解析・公開するため、これはクライアントの初期化成功を保証しない。
- `request_failed`：認証、受信、処理、送信、ACKのどこで失敗したかを記録する。
  実API失敗、期限超過、取消、検証拒否、内部処理の失敗を区別する。
  同じ失敗は60秒単位で抑制し、続く記録と接続口の定期記録に抑制件数を含む。
  正常な無接続待機の期限超過とbroker停止時の取消はエラーとして記録しない。

現行・直前の2ファイルをそれぞれ最大1 MiBに制限する。
直前のファイル名は `broker.previous.jsonl`。ディレクトリと新しいファイルには本人・SYSTEMの保護DACLを設定する。
ファイルへの同時書き込みとローテーションは専用lockで排他する。
記録先不良やlock競合では記録を諦め、初期取得や停止を継続する。
再解析ポイントを辿る保存は行わない。
この診断は接続口の復旧処理を追加するものではなく、5秒未満の短い状態変化を取り逃す場合がある。
`available` はbroker側からの名前の可視性を示し、AppContainer内の名前解決や認証・辞書取得の成功とは区別する。

### 検証範囲

`app_container` は一時的なAppContainerプロファイルを2つ作り、実際にそのトークンで子プロセスを起動する。
テスト用実行ファイルにだけ一時的な読み取り・実行ACEを追加し、終了時にACLとプロファイルを戻す。
辞書・設定は生成したfixtureを使い、私用ファイルを直接読めない状態でTSF・学習・推論を試す。
通常権限クライアントも同じfixture設定・辞書を取得することを検証する。
部分的な辞書・ローマ字の失敗で変換を継続し、学習要求を拒否することと、
同じbrokerへの再接続でサイズ・更新日時を変えない辞書・ローマ字の差し替えが反映されることも確認する。
未許可コンテナー、別の実行ファイル、古い設定、任意ファイル要求、AppContainerからのGUI要求の拒否も検証する。
`app_container_zenz` は設定済みの実モデルで文脈による採点と辞書にない読みの生成を確認する。

brokerの接続不良や初期化失敗では通常のかな入力は継続できる。
初回接続は成功までバックグラウンドで再試行し、brokerの起動が遅れても入力先の再起動を不要にする。
設定変更後・版更新後は入力先アプリを起動し直す。
任意のUWPアプリや別OS版のパッケージ名を自動的に許可しない。
実際のアプリでの確認範囲は [TSF検証](TSF_VALIDATION.md) に記録する。
