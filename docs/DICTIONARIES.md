# 辞書の利用

SKK辞書は読み取り専用で利用する。確定した候補の順位は別のユーザー辞書に保存し、
次の変換と他アプリの変換に反映する。単語登録と、CLIによる登録語の削除・書き出し・取り込みに対応する。
外部の共有辞書はリポジトリに同梱していない。

入力コアには候補確定時の学習イベントを用意した。`Result.learning` は読み・送りキー・
ひらがなの送り仮名・語幹の候補（注釈・出自を含む）を持ち、Enter、C-j、次の文字入力での
確定時に返す。取消、候補送り、かなの直接確定、未知語、リセットでは返さない。
`DoNotLearn` 指定と `GeneratedLong` の候補は対象外。abbrevのキーは大小文字を保つ。

これは保存前のイベントであり、Engine自身は辞書を更新しない。
ホストは本文への適用に成功してエンジンの新しい状態を採用した場合だけ配送する。
試行コピーの破棄や編集失敗では配送しない。フォーカス移動などホストによるcomposition終了も対象外。
CLIは `learning` フィールドを表示するだけで保存しない。
単語登録では `Result.registration` を付けて、同じ保存経路へ明示的に確定した語を渡す。
内側の登録でも確定時に配送し、外側の未確定登録とは分離する。

## CLI

```powershell
# UTF-8 / EUC-JPを自動判別
.\out\build\windows-x64\Release\skk_trace.exe --dict 'C:\辞書\SKK-JISYO.L' 'Kanji<Space><Enter>'

# 最初の辞書を優先。重複した表記と注釈は最初のものを採用
.\out\build\windows-x64\Release\skk_trace.exe --dict 'C:\辞書\user.skk' --dict 'C:\辞書\SKK-JISYO.L' 'KaKu<Enter>'

# 必要な場合は明示指定（すべての --dict に適用）
.\out\build\windows-x64\Release\skk_trace.exe --encoding utf-8 --dict .\tests\fixtures\basic.utf8.skk 'Jisho<Space><Enter>'

# abbrev: 英字見出しをそのまま検索する
.\out\build\windows-x64\Release\skk_trace.exe --dict .\tests\fixtures\basic.utf8.skk '/skk<Space><Enter>'
```

`--encoding` は `auto` / `utf-8` / `euc-jp`。`--dict` 省略時は内蔵の小さなテスト用辞書を使う。
キー列はASCII、Windowsのパス引数はUnicodeに対応する。標準出力はUTF-8のJSON Linesで、
候補一覧の `text`・`annotation` と選択位置 `candidate_index` を含む。
読み込み件数・診断は標準エラーへ出力する。ファイルが開けない、文字コードが不正などの
致命的なエラーでは終了コード2を返す。

## TSFの保存設定

```powershell
# 指定順に優先する。すべて読み込めることを確認してから設定を保存する
.\out\build\windows-x64\Release\nskkzime_config.exe --set-dictionaries 'C:\辞書\personal.skk' 'C:\辞書\SKK-JISYO.L'
.\out\build\windows-x64\Release\nskkzime_config.exe --show
.\out\build\windows-x64\Release\nskkzime_config.exe --check

# 学習を無効にする。onで再び有効にできる
.\out\build\windows-x64\Release\nskkzime_config.exe --set-learning off

# 辞書変換を無効にし、かな入力だけにする
.\out\build\windows-x64\Release\nskkzime_config.exe --disable-dictionaries
```

保存先はユーザーの `%LOCALAPPDATA%\nskkzime\settings.ini`。管理者権限は不要。
設定ファイルはUTF-8で、以下の形式を使う。パスは絶対パスで、引用符を付けず、
並べた順に優先する。空白・日本語・`=`・`#` を含むファイル名にも対応する。

```ini
version=1
learning=on
dictionary=C:\辞書\personal.skk
dictionary=C:\辞書\SKK-JISYO.L
```

行頭の `#` / `;` はコメント。UTF-8 BOMとCRLFにも対応する。
`learning=on` / `off` を指定でき、省略時はon。辞書設定を変更してもこの値は保持する。
`romaji=絶対パス` で独自のローマ字ルールも指定できる。設定CLIの `--set-romaji` / `--reset-romaji` で
切り替えられ、辞書や学習の設定を変更しても保持する。詳細は [ローマ字ルール](ROMAJI.md) を参照。
推論は省略時に無効。`--set-zenz モデル サーバー` / `--disable-inference` で設定できる。
対応キーと登録DLLの更新順序は [zenz CPUサーバー](ZENZ.md) を参照。推論設定も辞書の変更時に保持する。
最大32辞書、設定全体は64 KiBまで。未知のキー、重複したversion・learning・romaji、不正なUTF-8、
相対パス、制御文字を含むパスは拒否する。行の前後の空白は除く。
`version=1` だけのファイルは辞書なしを意味する。
保存は同じディレクトリの一時ファイルへ書き込み・フラッシュした後で置き換え、
書き込みや置換が失敗した場合は以前の設定を残す。

既定の設定ファイルが存在せず、上書き指定もない場合だけ内蔵テスト用辞書を使う。
設定が壊れている場合は空の辞書でかな入力を継続する。
複数辞書の一部だけが読めない場合は、読めた辞書を設定順に使う。
元の辞書ファイルは変更しない。GUIの設定画面は今後追加する。

検証アプリ下部には、**そのプロセスのDLLが読み込んだ**設定の場所、辞書パス、
件数、文字コード、スキップ数・行番号、読み込み失敗を表示する。
「状態を更新」は表示だけを更新し、辞書の再読み込みは行わない。
古い登録DLLが診断機能を持たない場合は、その旨を表示する。
`--check` は現在のファイルを読み込んで検査するため、起動済みアプリの状態とは異なる場合がある。
CLIの終了コードは正常・非致命的な行スキップが0、設定・辞書・ローマ字ルール・推論パスの検査失敗が2。

## 一時的な上書き設定

```powershell
$env:NSKKZIME_DICTIONARY = 'C:\辞書\SKK-JISYO.L'
# このPowerShellから検証対象アプリを新しく起動する
```

`NSKKZIME_DICTIONARY` には辞書1個の絶対パスを指定し、保存設定より優先する。
この開発用の隔離設定は保存されたローマ字ルール・推論設定も読まない。独自ルールを併用する場合は
`NSKKZIME_ROMAJI` にルールファイルの絶対パスを指定する。`builtin` なら内蔵ルールを強制する。
`NSKKZIME_CONFIG` には別の設定ファイルの絶対パスを指定できる。
明示指定した設定ファイルが存在しない場合はエラーとし、内蔵辞書には切り替えない。
設定CLIの `--config 'C:\設定\settings.ini'` は `NSKKZIME_CONFIG` より優先し、
そのファイルを表示・検査・保存する。`--check` 時の辞書上書きは引き続き有効。
環境変数はこのPowerShellと、その環境を継承した子プロセスだけに反映される。
既に動作しているアプリや、別の親プロセス経由で起動したアプリには反映されないことがある。
IMEの登録は別途 [TSFの検証](TSF_VALIDATION.md) の手順が必要。

サービスの最初のActivateでは小さな設定ファイルを読み、辞書本体はバックグラウンドで読み込む。
キー処理・準備状態の確認・診断表示はメモリーだけを参照する。同じプロセス内の同じ辞書設定では、
進行中の読み込みも完成後のスナップショットも共有する。辞書の優先順・学習設定・保存先が違う場合は分ける。
ファイルの変更は自動再読み込みしない。設定変更後は対象アプリを終了して起動し直す。
複数アプリ間の読み取り専用辞書の共有と永続キャッシュは未実装。
TSF表示属性を問い合わせるためだけに作られたCOMインスタンスでは辞書を読み込まない。

読み込み中でも、かな入力・読みの編集・かなのままの確定・取消は利用できる。
Spaceや送り仮名による変換要求は読みを保持し、辞書未登録とは扱わない。単語登録・生成推論も開始しない。
完了後はSpaceで再試行する。完了通知だけでは本文や入力状態を変更しないため、既に確定・取消した読みが戻ることはない。
読み込み失敗時は利用できる辞書とかな入力を残し、学習は停止する。学習先の設定は読み込み開始時の値を保持する。
終了時に読み込みを待つ処理はなく、実行中のワーカーが完了までDLLを保持する。
検証アプリの診断に「読み込み中」を表示し、`NskkzimeIsDictionaryReady` からも完了状態を確認できる。

読み込みエラーは検証アプリ・設定CLIで確認でき、`OutputDebugString` にも出す。

## 候補の学習と保存

保存設定に外部辞書があり、すべての辞書が読み込めた場合に学習を有効にする。
内蔵デモ辞書・辞書無効・設定不正・辞書読み込み失敗時には開始しない。
行単位のスキップは辞書全体の読み込み失敗には含めない。
`learning=off` は保存と学習済み順位の利用を止めるが、既存ファイルは消さない。
現在のWindows版では単語登録の開始も止める。登録の操作は [入力仕様](INPUT_SPEC.md#単語登録) を参照。

保存先は既定で `%LOCALAPPDATA%\nskkzime\user-dictionary.nskkdb`。
読み・送りキー・実際の送り仮名ごとに、確定した候補を先頭にする。
例えば「書く」の学習は「書け」の順位に影響しない。既存SKK辞書は書き換えない。
保存した候補は、ユーザー辞書・設定した共有辞書の順で統合する。
候補選択中の一覧は固定し、同期した順位は次の変換から利用する。

IMEと同じディレクトリにある `nskkzime_dictionary_server.exe` をバックグラウンドで自動起動する。
同じユーザー・保存先ごとに名前付きパイプと排他的なロックファイルを使い、書き込みを一つのプロセスに集約する。
パイプは当該ユーザーだけに許可し、ネットワーク越しの接続は受け付けない。
補助プロセスは接続のない状態が10秒続くと終了する。残った空の `.lock` ファイル自体はロックを意味しない。

キー処理はメモリー内の候補を検索し、確定後のイベントを最大128件のキューへ入れる。
IPC・ファイル保存・補助プロセス起動はワーカースレッドで行い、約1秒ごとに他プロセスの更新も取り込む。
IPCの期限は1回1.5秒、失敗後は250ms待って再試行し、補助プロセスの再起動試行は5秒以上あける。
保存は同じフォルダーへの一時書き込み・フラッシュ・置換の順で行い、成功後にだけ新しい順位を公開する。
送り手IDと連番も保存し、応答喪失後の再送で順位が二重に更新されたり、古い選択へ戻ったりすることを防ぐ。
保存失敗・壊れた保存ファイルでは通常の辞書変換を続け、既存データを空の辞書で上書きしない。

検証アプリの「状態を更新」で世代、未保存件数、受付不可件数、学習省略の理由を確認できる。
キューが一杯の場合は追加の学習を受け付けず、受付不可件数を増やす。
サービス終了後は最大5秒を目安に未保存分を送るが、アプリの強制終了・即時終了・保存失敗が続いた場合は
未保存分を失うことがある。保存済みのデータは再起動後にも利用できる。
電源断に対する絶対的な保存保証は提供しない。

変換範囲の `GUID_PROP_INPUTSCOPE` を本文変更前に読み、パスワード・private・PINの属性があれば学習しない。
取得失敗、属性なし、範囲内で属性が異なる場合も学習しない。属性を提供しないアプリでは
通常の変換だけを利用できる。ホストが属性を正しく申告することが前提で、本文から機密性を推測する仕組みはない。
検証アプリは普通のテキスト入力欄であることを `SetInputScope(IS_TEXT)` で明示する。

開発用の `NSKKZIME_DICTIONARY` 上書きでは学習を既定で無効にする。
`NSKKZIME_LEARNING=1` / `0` でそのプロセスの設定を上書きできる。
`NSKKZIME_USER_DICTIONARY` に絶対パスを指定すると保存先を変更できる。
`NSKKZIME_CONFIG` 使用時の既定保存先は、その設定ファイルと同じフォルダー。
同じ辞書を共有する各プロセスでは保存先を同じ綴りで指定する。
ジャンクション等の別名経由では同じIPC接続先と認識しない（ロックにより同時書き込みは拒否する）。

ユーザー辞書は長さ付きUTF-8とチェックサムを持つ独自形式。
通常の学習だけなら従来の `NKUD1` を使い、送りを限定しない送りあり候補の取り込み後は `NKUD2` を使う。
新しい版は両形式を読める。古いIME・補助プロセスは `NKUD2` を扱えないため、取り込み前に両方を更新する。
SKK-JISYOとして直接編集せず、書き出し・取り込みには下記のCLIを使う。
上限は16 MiB、50,000組の読み／送り、1組32候補、65,536個の送り手ID。
上限に達した場合の整理機能は今後追加する。

## 登録・学習した語の管理

```powershell
# 保存済みの語をJSON Linesで表示。読み、送りキー、送り仮名、表記、注釈の順
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --list

# 「かんじ」の「感じ」だけをユーザー辞書から削除
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --forget 'かんじ' '感じ'

# 送りありでは語幹と、英小文字1字の送りキー・ひらがなの送りを指定
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --forget 'か' '描' --okuri k 'く'

# 新しいUTF-8 SKKファイルへ書き出す。既存ファイルは上書きしない
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --export 'C:\辞書\nskkzime-export.skk'

# 取り込みを事前検査してから、既存順位を保って追加する
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --check-import 'C:\辞書\my-skk-jisyo'
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --import 'C:\辞書\my-skk-jisyo'

# 取り込んだ「かk」の共通候補だけを削除。送り「く」などの個別候補は保つ
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --forget 'か' '描' --okuri-key k

# 別の保存ファイルを管理する場合（環境変数より優先）
.\out\build\windows-x64\Release\nskkzime_user_dictionary.exe --file 'C:\検証\user-dictionary.nskkdb' --list
```

既定の保存先はIMEと同じで、`NSKKZIME_USER_DICTIONARY` / `NSKKZIME_CONFIG` にも従う。
一覧と書き出しは保存済みの一つの世代を読み、IME内の未保存キューは含めない。
一覧は読み／送りの順、同じ見出しの中は候補順位の順。出力はUTF-8。
ファイルが未作成なら空として扱い、壊れている場合はエラー終了して書き出さない。

削除は補助プロセスへ送り、ディスク保存の成功を確認してから完了する。
読み・送りキー・送り仮名・表記がすべて一致する語だけを対象とし、該当語がない場合も成功する。
`--okuri-key k` は送りを限定しない「かk」の共通候補、`--okuri k く` は送り「く」の候補だけを対象とする。
一覧では共通候補を空の `okuri` として表示する。`--okuri` に空文字列は指定しない。
再送の重複排除は学習と共通で、古い削除要求の再送によって新しく登録し直した語を消さない。
他アプリには通常約1秒で反映し、既に選択中の候補一覧は変更しない。
登録直後の一時キャッシュも、保存完了後は共有辞書の状態に従う。
共有辞書に同じ語があれば元の順位で引き続き候補になる。候補の禁止機能ではない。
削除後にその語を再度確定した場合や、他アプリの未保存学習が後から届いた場合は再び保存される。
学習がoffでもこの管理CLIは利用できる。IME内の削除キーとGUI管理画面は未実装。

書き出しでは、送りありを降順・送りなしを昇順に並べ、候補順位と注釈を保つ。
`/`・`;`・括弧などは、引用文字列だけの `concat` とエスケープで表す。
送り別の語はブロック内だけに置くため、別の送りへの候補の拡大を避けられる。
このファイルを読む側には送り仮名ブロックと文字列concatへの対応が必要で、全SKK実装との互換性は未検証。
nskkzimeでは通常の読み取り専用辞書として設定できる。学習用ファイルそのもののバックアップ形式ではなく、
出自・内部ID・世代・再送用の情報は書き出さない。
SKKで表現できない見出し（空白や先頭`;`など）・文字・長すぎる行があれば、全体をエラーとして既存ファイルを残す。
終了コードは成功0、引数不正・読み込み・保存・通信エラー2。

古い版の補助プロセスは新しい削除・取り込み要求を受け付けない。その場合は利用アプリを終了し、補助プロセスが
通常の待機終了（10秒）をした後で再実行する。CLIは既存プロセスを強制終了しない。
書式は [DDSKKの辞書形式と送り仮名ブロック](https://ddskk.readthedocs.io/ja/latest/06_apps.html) を参照。

## SKKユーザー辞書の取り込み

`--import` は通常のSKKファイルを学習用辞書へ追加する。入力は絶対パスで指定し、元ファイルを変更しない。
UTF-8／EUC-JPを自動判定する。末尾に `--encoding utf-8` または `--encoding euc-jp` を付けて明示できる。
対応する文字コード・concat・送り仮名ブロックは読み取り専用辞書と同じ。EUC-JPのSS3補助漢字も直接取り込める。

- 読み・送りキー・送り仮名が同じ組の既存候補は、順位と注釈を保つ。新しい表記を入力ファイルの順で末尾へ追加する。
- 送りを限定しない候補と、`[く/…/]` のような送り別の候補を別々に保存する。
  検索では送り別の候補を優先してから共通候補を追加し、同じ表記を重複表示しない。
- 不正な行、未対応の候補式、保存できない値が1件でもあれば全体を拒否する。候補式は実行しない。
  通常の読み取り専用辞書で行う「読める部分だけを使う」処理は、取り込みには適用しない。
- 1回50,000候補、通信データ16 MiBまで。追加後も保存先の16 MiB・50,000組・1組32候補の上限を検査する。
  上限超過で既存語や下位候補を削らず、全体をエラーにする。大規模な共有辞書は読み取り専用辞書として設定する。
- `--check-import` は元ファイルと保存先のスナップショットを検査し、追加・重複の件数を表示する。
  保存も補助プロセスの起動も行わない。件数は検査時点の値であり、保存先の書き込み権限まで保証するものではない。
- 実際の保存は補助プロセスが最新の辞書へ一括適用する。他アプリの学習を上書きせず、保存に失敗した場合は
  ディスク上の辞書とプロセス内の候補の両方を保つ。空の入力ファイルでは何も保存しない。
- 通信失敗時の再送は同じ要求IDを使う。保存後に削除された語を、古い再送で復活させない。
  CLIを改めて実行した場合は新しい取り込みなので、削除済みの語も再び追加される。

読み込み・保存・通信エラーは終了コード2。通信結果を確認できない場合は `--list` で保存状態を確認する。
書き出したSKKファイルも再取り込みできるが、世代・再送履歴・生成候補としての出自は移さず通常の辞書候補になる。

## 対応する形式

| 項目 | 現在の扱い |
|---|---|
| 文字コード | UTF-8、Windows上のEUC-JP（SS2半角カナ・SS3補助漢字を含む）。BOM、先頭行の `coding:`、内容の順で判別 |
| 改行 | LF、CRLF、末尾の改行なし |
| セクション | `;; okuri-ari entries.` / `;; okuri-nasi entries.` |
| セクションなし | ひらがなを含み末尾が英小文字の見出しを送りありと推定。それ以外は送りなし |
| 見出しと候補 | `読み /候補1;注釈/候補2/`。並び順を保持し、同じ見出しの複数行は統合 |
| 送りあり | `かk /書/描/`。検索キーは「か」＋`k` |
| 送り仮名別候補 | `おおk /大/多/[く/多/]/[き/大/]/`。一致する送りの候補を先に提示 |
| 特殊文字 | `(concat "I\057O")` など、引用文字列だけのconcat。八進エスケープ、`\\`、`\"` を解釈 |
| 括弧付きの日本語 | `(株)`・`(笑)` はそのままの表記として保持 |
| Lisp式 | 実行しない。未対応の候補式はスキップ。注釈の未対応式は文字列として保持 |
| 数値変換・動的候補 | `#` の展開、日付などの関数呼び出しは未対応 |

文字コードの自動判別ではUTF-8 BOMを最優先する。BOMがなければ先頭コメント行の
`coding: utf-8` / `utf-8-unix` / `euc-jp` / `euc-jp-unix` を使う。
指定がなければ厳密なUTF-8として読み、失敗した場合にEUC-JPを試す。
未対応のcoding指定はエラーとする。`--encoding` はcoding指定を上書きするが、BOMとの矛盾は拒否する。
通常のEUC-JPとSS2はWindowsコードページ20932を使い、バイト列の妥当性と往復変換での一致を確認する。
SS3（`8F A1..FE A1..FE`、JIS X 0212）は[Unicodeの対応表](https://www.unicode.org/Public/MAPPINGS/OBSOLETE/EASTASIA/JIS/JIS0212.TXT)の
v2.0を固定して解釈する。割当済みの6,067文字を候補・見出し・注釈で利用でき、未割当位置・途中で切れた列・
不正なバイトは辞書全体をエラーにする。表のJIS `0x2237` は `U+007E`（半角チルダ）になる。
版・チェックサム・ライセンスと再生成手順は [依存データ](../third_party/README.md) を参照。
EUC-JIS-2004は未対応で、coding指定時はエラーとする。同じSS3形でもJIS X 0213とは対応表が異なるため、
EUC-JIS-2004を `euc-jp` と指定しない。該当する辞書は対応したエディターなどでUTF-8として別名保存し、
先頭のcoding指定も `utf-8` に変更して使う。Windows以外でもUTF-8の辞書を使う。

候補内の改行・タブ・空文字列には未対応。辞書全体は128 MiB、1行は65,536コードポイントまで。
壊れた行は行単位でスキップし、未対応候補は候補単位でスキップする。
件数と先頭32件の行番号・理由を報告する。診断には見出し・候補本文を含めない。
候補数は送り仮名別ブロックを含む、格納した候補の延べ数である。
