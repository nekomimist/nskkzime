# 辞書の利用

SKK辞書は読み取り専用で利用する。確定した候補の順位は別のユーザー辞書に保存し、
次の変換と他アプリの変換に反映する。単語登録と、CLIによる登録語の削除・書き出し・取り込みに対応する。
外部の共有辞書はリポジトリに同梱していない。

入力コアには候補確定時の学習イベントを用意した。`Result.learning` は読み・送りキー・
ひらがなの送り仮名・語幹の候補（注釈・出自を含む）を持ち、Enter、C-j、次の文字入力での
確定時に返す。取消、候補送り、かなの直接確定、未知語、リセットでは返さない。
`DoNotLearn` 指定と `GeneratedLong` の候補は対象外。abbrevのキーは大小文字を保つ。

これは保存前のイベントであり、Engine自身は辞書を更新しない。
ホストは本文への適用に成功してエンジンの新しい状態を採用した場合だけ配送する。
試行コピーの破棄や編集失敗では配送しない。フォーカス移動などホストによるcomposition終了も対象外。
CLIは `learning` フィールドを表示するだけで保存しない。
単語登録では `Result.registration` を付けて、同じ保存経路へ明示的に確定した語を渡す。
内側の登録でも確定時に配送し、外側の未確定登録とは分離する。

## CLI

```powershell
# UTF-8 / EUC-JPを自動判別
.\out\build\windows-x64-zenz\Release\skk_trace.exe --dict 'C:\辞書\SKK-JISYO.L' 'Kanji<Space><Enter>'

# 最初の辞書を優先。重複した表記と注釈は最初のものを採用
.\out\build\windows-x64-zenz\Release\skk_trace.exe --dict 'C:\辞書\user.skk' --dict 'C:\辞書\SKK-JISYO.L' 'KaKu<Enter>'

# 必要な場合は明示指定（すべての --dict に適用）
.\out\build\windows-x64-zenz\Release\skk_trace.exe --encoding utf-8 --dict .\tests\fixtures\basic.utf8.skk 'Jisho<Space><Enter>'

# abbrev: 英字見出しをそのまま検索する
.\out\build\windows-x64-zenz\Release\skk_trace.exe --dict .\tests\fixtures\basic.utf8.skk '/skk<Space><Enter>'
```

`--encoding` は `auto` / `utf-8` / `euc-jp`。`--dict` 省略時は内蔵の小さなテスト用辞書を使う。
キー列はASCII、Windowsのパス引数はUnicodeに対応する。標準出力はUTF-8のJSON Linesで、
候補一覧の `text`・`annotation` と選択位置 `candidate_index` を含む。
読み込み件数・診断は標準エラーへ出力する。ファイルが開けない、文字コードが不正などの
致命的なエラーでは終了コード2を返す。

## TSFの保存設定

```powershell
# 指定順に優先する。すべて読み込めることを確認してから設定を保存する
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-dictionaries 'C:\辞書\personal.skk' 'C:\辞書\SKK-JISYO.L'
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --show
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --check

# 学習を無効にする。onで再び有効にできる
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-learning off

# 辞書変換を無効にし、かな入力だけにする
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --disable-dictionaries
```

保存先はユーザーの `%LOCALAPPDATA%\nskkzime\settings.ini`。管理者権限は不要。
設定ファイルはUTF-8で、以下の形式を使う。パスは絶対パスで、引用符を付けず、
並べた順に優先する。空白・日本語・`=`・`#` を含むファイル名にも対応する。

```ini
version=1
learning=on
dictionary=C:\辞書\personal.skk
dictionary=C:\辞書\SKK-JISYO.L
```

行頭の `#` / `;` はコメント。UTF-8 BOMとCRLFにも対応する。
`learning=on` / `off` を指定でき、省略時はon。辞書設定を変更してもこの値は保持する。
`romaji=絶対パス` で独自のローマ字ルールも指定できる。設定CLIの `--set-romaji` / `--reset-romaji` で
切り替えられ、辞書や学習の設定を変更しても保持する。詳細は [ローマ字ルール](ROMAJI.md) を参照。
推論は省略時に無効。`--set-zenz モデル` / `--disable-inference` で設定できる（サーバーは同梱版。2番目の引数は開発用の上書き）。
対応キーと登録DLLの更新順序は [zenz CPUサーバー](ZENZ.md) を参照。推論設定も辞書の変更時に保持する。
最大32辞書、設定全体は64 KiBまで。未知のキー、重複したversion・learning・romaji、不正なUTF-8、
相対パス、制御文字を含むパスは拒否する。行の前後の空白は除く。
`version=1` だけのファイルは辞書なしを意味する。
保存は同じディレクトリの一時ファイルへ書き込み・フラッシュした後で置き換え、
書き込みや置換が失敗した場合は以前の設定を残す。

既定の設定ファイルが存在せず、上書き指定もない場合だけ内蔵テスト用辞書を使う。
設定が壊れている場合は空の辞書でかな入力を継続する。
複数辞書の一部だけが読めない場合は、読めた辞書を設定順に使う。
元の辞書ファイルは変更しない。同じ保存設定を以下のGUIからも編集できる。

検証アプリ下部には、**そのプロセスのDLLが読み込んだ**設定の場所、辞書パス、
件数、文字コード、スキップ数・行番号、読み込み失敗を表示する。
「状態を更新」は表示だけを更新し、辞書の再読み込みは行わない。
古い登録DLLが診断機能を持たない場合は、その旨を表示する。
`--check` は現在のファイルを読み込んで検査するため、起動済みアプリの状態とは異なる場合がある。
CLIの終了コードは正常・非致命的な行スキップが0、設定・辞書・ローマ字ルール・推論パスの検査失敗が2。

## 設定GUI

```powershell
.\out\build\windows-x64-zenz\Release\nskkzime_settings.exe
# 日常の設定とは別のファイルを編集する場合
.\out\build\windows-x64-zenz\Release\nskkzime_settings.exe --config 'C:\検証\settings.ini'
```

既定では上記の `settings.ini` を開く。`NSKKZIME_CONFIG` による保存先指定にも対応し、
`--config` はそれより優先する。画面の上部に保存先を表示する。
初めて開く場合は保存するまでファイルを作らない。空の辞書設定を保存すると内蔵テスト辞書は使わなくなる。
既存設定が不正・読み込み不能の場合は編集と保存を停止し、元ファイルを直して「再読込」で戻る。

| タブ | 編集できる項目 |
|---|---|
| 辞書 | 最大32個の追加・複数選択、優先順の上下移動、一覧から外す操作、学習の有効／無効 |
| ローマ字 | 独自ルールの有効／無効、UTF-8ルールファイル |
| 推論 | zenzの有効／無効、GGUFモデルとサーバー、候補採点、短い追加生成語の学習 |
| 詳細 | 推論スレッド数、生成・採点の期限、サーバーの待機秒数、表示前の採点待ち時間、長い読みの文字数、採点候補数とスコア差 |
| 診断 | 既定オフの入力ログ、読み・前後本文・候補を保存するローカルフォルダー |
| 文脈 | 入力属性が不明なアプリでの周辺本文取得の許可 |
| 候補一覧 | 一覧を出すまでのSpace回数（1～99）、選択キー（1–7／ASDFJKL） |

「候補一覧」の既定値は1回目から表示・1–7で選択で、既存の設定と動作は変わらない。
変換開始を1回目として、その後のSpaceごとに回数を増やす。送り仮名による自動変換も1回目と数える。
たとえば3にすると、最初の候補と次候補は本文内だけに表示し、3回目から一覧を開く。
zenzの候補追加・並べ替えでは回数を増やさない。一度開いた一覧はxで戻っても表示し続ける。
PgDn／PgUpは回数を待たず一覧を開く。登録欄・削除確認欄はこの設定で遅らせない。
ASDFJKLはShiftなしの `a/s/d/f/j/k/l` で表示中の7行を選ぶ。一覧が出るまでは通常の続け打ちになり、
ASDFJKL設定時の数字も通常の文字入力として扱う。保存後は利用するアプリを起動し直す。

CLIでも設定できる。回数・選択キーの省略時はそれぞれ1・numbers。既存の辞書・推論設定を保持する。

```powershell
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-candidate-show-after 3
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-candidate-keys asdfjkl
# 従来の動作へ戻す
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-candidate-show-after 1
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-candidate-keys numbers
```

保存形式は `candidate-show-after=3`、`candidate-keys=asdfjkl`。既定値の項目は保存時に省略する。

「検査する」は編集内容を保存せず検査する。「保存」も同じ検査を通してから書き込む。
辞書・ローマ字の読み込みはバックグラウンドで行い、検査中は編集を止めるが画面は閉じられる。
存在しない辞書や不正なローマ字、範囲外の数値は保存しない。辞書内の非致命的な不正行は件数・行番号を表示して保存できる。
推論が有効な場合はモデルとサーバーの存在を確認するだけで、モデル形式の検査・推論の実行・ダウンロードは行わない。
推論をオフにしてもパスと方針は保持する。ローマ字をオフにすると保存された独自ルール指定を外す。

未保存の編集はタイトルに表示し、閉じる・再読み込み時に破棄の確認を出す。
検査中に閉じる場合も、破棄確認への応答を待つ間は保存を進めない。
保存失敗時は編集内容を残す。読み込み時からファイルが更新・作成・削除されていれば保存を拒否する。
この照合と置換は他の編集ソフトとロックを共有しないため、照合直後の同時書き込みを完全には防がない。
`NSKKZIME_DICTIONARY` 等の実行時上書きはGUIの検査には適用せず、保存設定自体を検査する。
保存後はIMEを使うアプリを終了して起動し直す。
入力ログの有効化・無効化にも再起動が必要。保存範囲と容量上限は [診断用入力ログ](DIAGNOSTICS.md) を参照。

「外す」は設定一覧からの除外で、元の辞書ファイルは削除しない。学習した語の一覧・削除・取り込みは管理CLI／GUIを使う。
GUIは単独の実行ファイル、またはIMEの入力モードメニューの「設定…」から起動する。
メニューからは、そのIMEが初回の有効化時に取得した設定ファイルの絶対パスを `--config` で渡す。
`NSKKZIME_CONFIG` の一時指定も引き継ぐ。不正な相対パス等の場合はメニュー項目を無効にし、既定ファイルへ切り替えない。
DLLと同じフォルダーのGUIを別プロセスで起動し、入力スレッドは起動完了を待たない。
起動に失敗した場合はWindowsエラー番号を表示する。登録時の配置には両GUIも必要で、`register-dev.ps1` がまとめて配置する。
メニューのコールバックと実GUIの起動・保存先表示は検証済み。Windows上のメニュー表示・操作はIME再登録後に確認する。
2026-10-06に隔離した設定で4タブ、辞書の追加・順序変更、日本語と空白のパス、独自ルールの保存、
範囲外の数値、未保存確認、外部変更の拒否・再読み込み、アクセスキーとTab移動を実画面で確認した。
Debug版で10万見出しの辞書を8回読み込む検査中に終了確認を開き、確認中の保存停止、
「いいえ」で保存再開、「はい」で保存せず終了する動作を保存ファイルの更新時刻と照合した。
DPI変更・複数ディスプレイの実測は残る。

## 一時的な上書き設定

```powershell
$env:NSKKZIME_DICTIONARY = 'C:\辞書\SKK-JISYO.L'
# このPowerShellから検証対象アプリを新しく起動する
```

`NSKKZIME_DICTIONARY` には辞書1個の絶対パスを指定し、保存設定より優先する。
この開発用の隔離設定は保存されたローマ字ルール・推論設定も読まない。独自ルールを併用する場合は
`NSKKZIME_ROMAJI` にルールファイルの絶対パスを指定する。`builtin` なら内蔵ルールを強制する。
`NSKKZIME_CONFIG` には別の設定ファイルの絶対パスを指定できる。
明示指定した設定ファイルが存在しない場合はエラーとし、内蔵辞書には切り替えない。
設定CLIの `--config 'C:\設定\settings.ini'` は `NSKKZIME_CONFIG` より優先し、
そのファイルを表示・検査・保存する。`--check` 時の辞書上書きは引き続き有効。
環境変数はこのPowerShellと、その環境を継承した子プロセスだけに反映される。
既に動作しているアプリや、別の親プロセス経由で起動したアプリには反映されないことがある。
IMEの登録は別途 [TSFの検証](TSF_VALIDATION.md) の手順が必要。

サービスの最初のActivateでは小さな設定ファイルを読み、辞書本体はバックグラウンドで読み込む。
キー処理・準備状態の確認・診断表示はメモリーだけを参照する。同じプロセス内の同じ辞書設定では、
進行中の読み込みも完成後のスナップショットも共有する。辞書の優先順・学習設定・保存先が違う場合は分ける。
ファイルの変更は自動再読み込みしない。設定変更後は対象アプリを終了して起動し直す。
読み取り専用辞書は永続キャッシュと共有メモリーを使い、複数アプリで解析結果を再利用する。
TSF表示属性を問い合わせるためだけに作られたCOMインスタンスでは辞書を読み込まない。

読み込み中でも、かな入力・読みの編集・かなのままの確定・取消は利用できる。
Spaceや送り仮名による変換要求は読みを保持し、辞書未登録とは扱わない。単語登録・生成推論も開始しない。
完了後はSpaceで再試行する。完了通知だけでは本文や入力状態を変更しないため、既に確定・取消した読みが戻ることはない。
読み込み失敗時は利用できる辞書とかな入力を残し、学習は停止する。学習先の設定は読み込み開始時の値を保持する。
終了時に読み込みを待つ処理はなく、実行中のワーカーが完了までDLLを保持する。

## 読み取り専用辞書のキャッシュ

保存設定を使うTSFでは、設定ファイルと同じフォルダーの `dictionary-cache-v1` に解析済み辞書を保存する。
通常の保存先は `%LOCALAPPDATA%\nskkzime\dictionary-cache-v1`。
同じキャッシュ先を使う、同じユーザー・Windowsセッション内のアプリは、読み取り専用の共有メモリーを参照する。
最後の参照がなくなると共有メモリーは解放される。次の起動ではディスクのキャッシュを読み、再び共有する。
学習用辞書の保存・同期は従来の補助プロセスが担当し、このキャッシュには入力履歴や確定語を追加しない。
ただし、設定したSKKファイルの見出し・候補・注釈はキャッシュに複製される。

バックグラウンドで元ファイルを読み、内容のSHA-256・指定文字コード・解析形式の版からキャッシュを選ぶ。
更新日時とサイズが同じ変更も検出する。元ファイルがない・読めない場合に、古いキャッシュで補うことはしない。
キャッシュを使う場合も元ファイルの読み込みと形式検証は必要で、ディスクアクセス全体を省略する仕組みではない。
起動済みアプリは取得済みのスナップショットを保つため、元辞書の更新後は対象アプリを起動し直す。

保存ファイルはチェックサム、長さ、索引の順序、オフセット、Unicode値を検査する。
破損や途中までの保存を検出した場合は元辞書から作り直す。保存は一時ファイルのフラッシュ後に置き換える。
同時作成はファイルロックで直列化し、5秒以内に取得できない場合は通常の辞書解析に戻る。
キャッシュ先が書けない・容量が足りないなどの場合も、元辞書が正常なら通常の変換・学習を続ける。
これらの処理や待機はキー処理スレッドでは行わない。

永続ファイルを直接メモリーマップせず、`ReadFile` で読んだ検査済みデータをページファイルを使う
共有領域へ移す。初期化用の書き込みビューを閉じてから読み取り専用ビューを公開し、共有領域のACLも
現在のユーザーによる読み取りに制限する。索引にはプロセス固有のポインターを保存しない。
これはファイルビューへのアクセスで発生し得るI/O例外を、キー処理時に持ち込まないための設計。
Windowsの動作は [MapViewOfFile](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile) と
[LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex) を参照。

1個の解析済みデータは512 MiBまで。新規保存時には、同じフォルダー内のこの版のキャッシュだけを古い順に整理し、
64ファイル・合計1 GiB以内を目安に保つ。削除失敗時は超過が残る場合がある。無関係な名前のファイルは削除しない。
キャッシュだけを消しても元辞書や学習データは失われず、次の読み込みで再作成する。

開発時は `NSKKZIME_DICTIONARY_CACHE` に絶対パスを指定して保存先を変えられる。`off` で無効にできる。
`NSKKZIME_DICTIONARY` による一時辞書指定では既定でキャッシュを使わず、必要なら保存先も明示する。
内蔵テスト辞書・設定の検査CLI・辞書の取り込みCLIではキャッシュを作らない。
検証アプリの辞書診断には「キャッシュ作成」「永続キャッシュ」「共有キャッシュ」または通常読み込みへの復帰を表示する。

キャッシュは再作成可能な内部形式であり、辞書の配布・交換形式には使わない。
現在の封筒形式は `NSKKCF01`、索引形式は `NSKKDC01`。整数はlittle endian、文字列はUTF-32で、診断のみUTF-8。
解析規則・文字コード対応表・候補IDの規則を変更するときは、キャッシュキーと保存形式の版も更新して旧結果を再利用しない。
検証アプリの診断に「読み込み中」を表示し、`NskkzimeIsDictionaryReady` からも完了状態を確認できる。

読み込みエラーは検証アプリ・設定CLIで確認でき、`OutputDebugString` にも出す。

## 候補の学習と保存

保存設定に外部辞書があり、すべての辞書が読み込めた場合に学習を有効にする。
内蔵デモ辞書・辞書無効・設定不正・辞書読み込み失敗時には開始しない。
行単位のスキップは辞書全体の読み込み失敗には含めない。
`learning=off` は保存と学習済み順位の利用を止めるが、既存ファイルは消さない。
現在のWindows版では単語登録の開始も止める。登録の操作は [入力仕様](INPUT_SPEC.md#単語登録) を参照。

保存先は既定で `%LOCALAPPDATA%\nskkzime\user-dictionary.nskkdb`。
読み・送りキー・実際の送り仮名ごとに、確定した候補を先頭にする。
例えば「書く」の学習は「書け」の順位に影響しない。既存SKK辞書は書き換えない。
保存した候補は、ユーザー辞書・設定した共有辞書の順で統合する。
候補選択中の一覧は固定し、同期した順位は次の変換から利用する。

IMEと同じディレクトリにある `nskkzime_dictionary_server.exe` をバックグラウンドで自動起動する。
同じユーザー・保存先ごとに名前付きパイプと排他的なロックファイルを使い、書き込みを一つのプロセスに集約する。
パイプは当該ユーザーだけに許可し、ネットワーク越しの接続は受け付けない。
補助プロセスは接続のない状態が10秒続くと終了する。残った空の `.lock` ファイル自体はロックを意味しない。
補助プロセスは書き込み専用で、未保存の学習・削除があるときだけ起動する。

キー処理はメモリー内の候補を検索し、確定後のイベントを最大128件のキューへ入れる。
IPC・ファイル保存・補助プロセス起動はワーカースレッドで行う。他プロセスの更新は、保存ファイルを直接読んで取り込む。
補助プロセスは保存のたびに、置き換えた世代の名前付きイベント（同じユーザー限定）を通知する。
各IMEは手元の世代のイベントを待ち、通知を受けたらファイルを読み直す。定期的な問い合わせは行わず、
通知の取りこぼしに備えて60秒ごとにファイル先頭の世代だけを確認する。
IPCの期限は1回1.5秒。失敗後の再試行は250msから最大5秒まで間隔を広げ、
補助プロセスの起動試行は5秒から最大5分まで間隔を倍にする（壊れた保存ファイルで起動できない場合の多重起動を防ぐ）。
AppContainerのIMEは従来どおりbroker経由で約1秒ごとに確認するが、brokerは保存ファイルを直接読み、補助プロセスを起動しない。
保存は同じフォルダーへの一時書き込み・フラッシュ・置換の順で行い、成功後にだけ共有の順位を公開する。
同じプロセス内では、未保存の学習・削除も受付順に検索結果へ反映する。
送り手IDと連番も保存し、応答喪失後の再送で順位が二重に更新されたり、古い選択へ戻ったりすることを防ぐ。
保存失敗・壊れた保存ファイルでは通常の辞書変換を続け、既存データを空の辞書で上書きしない。

検証アプリの「状態を更新」で世代、未保存件数、受付不可件数、学習省略の理由を確認できる。
キューが一杯の場合は追加の学習・削除を受け付けず、受付不可件数を増やす。
サービス終了後は最大5秒を目安に未保存分を送るが、アプリの強制終了・即時終了・保存失敗が続いた場合は
未保存分を失うことがある。保存済みのデータは再起動後にも利用できる。
電源断に対する絶対的な保存保証は提供しない。

変換範囲の `GUID_PROP_INPUTSCOPE` を本文変更前に読み、パスワード・private・PINの属性があれば学習しない。
Office等、属性を提供しないアプリ（取得失敗・属性なし・範囲内で属性が異なる場合を含む）は保護された欄とみなさず、
通常の欄と同じく学習・単語登録・削除を行う。標準EDITの `ES_PASSWORD` は属性とは別に判定してIME自体を止める。
ホストが保護属性を正しく申告することが前提で、本文から機密性を推測する仕組みはない。
検証アプリは普通のテキスト入力欄であることを `SetInputScope(IS_TEXT)` で明示する。

開発用の `NSKKZIME_DICTIONARY` 上書きでは学習を既定で無効にする。
`NSKKZIME_LEARNING=1` / `0` でそのプロセスの設定を上書きできる。
`NSKKZIME_USER_DICTIONARY` に絶対パスを指定すると保存先を変更できる。
`NSKKZIME_CONFIG` 使用時の既定保存先は、その設定ファイルと同じフォルダー。
同じ辞書を共有する各プロセスでは保存先を同じ綴りで指定する。
ジャンクション等の別名経由では同じIPC接続先と認識しない（ロックにより同時書き込みは拒否する）。

ユーザー辞書は長さ付きUTF-8とチェックサムを持つ独自形式。
通常の学習だけなら従来の `NKUD1` を使い、送りを限定しない送りあり候補の取り込み後は `NKUD2` を使う。
新しい版は両形式を読める。古いIME・補助プロセスは `NKUD2` を扱えないため、取り込み前に両方を更新する。
SKK-JISYOとして直接編集せず、書き出し・取り込みには下記のCLIを使う。
上限は16 MiB、50,000組の読み／送り、1組32候補。
送り手IDはIMEのプロセスごとに作られるため、最近書き込んだ1,024個だけを保持し、古いものから捨てる。
再送の重複排除は数秒以内の再試行を対象とするため、これで不足しない。旧版が保存した最大65,536個のIDも読め、次の保存で整理する。
読み／送りの上限に達した場合の整理機能は今後追加する。

## 登録・学習した語の管理

```powershell
# 保存済みの語をJSON Linesで表示。読み、送りキー、送り仮名、表記、注釈の順
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --list

# 「かんじ」の「感じ」だけをユーザー辞書から削除
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --forget 'かんじ' '感じ'

# 送りありでは語幹と、英小文字1字の送りキー・ひらがなの送りを指定
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --forget 'か' '描' --okuri k 'く'

# 新しいUTF-8 SKKファイルへ書き出す。既存ファイルは上書きしない
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --export 'C:\辞書\nskkzime-export.skk'

# 取り込みを事前検査してから、既存順位を保って追加する
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --check-import 'C:\辞書\my-skk-jisyo'
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --import 'C:\辞書\my-skk-jisyo'

# 取り込んだ「かk」の共通候補だけを削除。送り「く」などの個別候補は保つ
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --forget 'か' '描' --okuri-key k

# 別の保存ファイルを管理する場合（環境変数より優先）
.\out\build\windows-x64-zenz\Release\nskkzime_user_dictionary.exe --file 'C:\検証\user-dictionary.nskkdb' --list
```

既定の保存先はIMEと同じで、`NSKKZIME_USER_DICTIONARY` / `NSKKZIME_CONFIG` にも従う。
一覧と書き出しは保存済みの一つの世代を読み、IME内の未保存キューは含めない。
一覧は読み／送りの順、同じ見出しの中は候補順位の順。出力はUTF-8。
ファイルが未作成なら空として扱い、壊れている場合はエラー終了して書き出さない。

削除は補助プロセスへ送り、ディスク保存の成功を確認してから完了する。
読み・送りキー・送り仮名・表記がすべて一致する語だけを対象とし、該当語がない場合も成功する。
`--okuri-key k` は送りを限定しない「かk」の共通候補、`--okuri k く` は送り「く」の候補だけを対象とする。
一覧では共通候補を空の `okuri` として表示する。`--okuri` に空文字列は指定しない。
再送の重複排除は学習と共通で、古い削除要求の再送によって新しく登録し直した語を消さない。
他アプリには保存後の通知ですぐに反映し、既に選択中の候補一覧は変更しない。
登録直後の一時キャッシュも、保存完了後は共有辞書の状態に従う。
共有辞書に同じ語があれば元の順位で引き続き候補になる。候補の禁止機能ではない。
削除後にその語を再度確定した場合や、他アプリの未保存学習が後から届いた場合は再び保存される。
学習がoffでも管理CLI／GUIは利用できる。

学習が有効なIMEでは候補選択中に `X` を押すと、選択語と読み・送り範囲の確認欄が開く。
`yes`＋Enterで確認した登録だけを削除し、元の読みに戻る。Escape／C-g／`no`＋Enterでは候補へ戻る。
送り別の登録があればそれを優先し、なければ共通候補を対象にする。
確認開始後の辞書更新で対象を別の送りへ変更しない。本文編集が成功した後で非同期配送し、失敗時は再送する。
確認中に入力欄を離れたり、属性が保護／不明になった場合には削除しない。
同じIMEでは未保存の学習・削除も順番に検索へ反映する。読み取り専用辞書の同じ表記は引き続き使える。
詳しい取消・登録欄内の動作は [入力仕様](INPUT_SPEC.md#候補から学習語を削除) を参照。

書き出しでは、送りありを降順・送りなしを昇順に並べ、候補順位と注釈を保つ。
`/`・`;`・括弧などは、引用文字列だけの `concat` とエスケープで表す。
送り別の語はブロック内だけに置くため、別の送りへの候補の拡大を避けられる。
このファイルを読む側には送り仮名ブロックと文字列concatへの対応が必要で、全SKK実装との互換性は未検証。
nskkzimeでは通常の読み取り専用辞書として設定できる。学習用ファイルそのもののバックアップ形式ではなく、
出自・内部ID・世代・再送用の情報は書き出さない。
SKKで表現できない見出し（空白や先頭`;`など）・文字・長すぎる行があれば、全体をエラーとして既存ファイルを残す。
終了コードは成功0、引数不正・読み込み・保存・通信エラー2。

古い版の補助プロセスは新しい削除・取り込み要求を受け付けない。その場合は利用アプリを終了し、補助プロセスが
通常の待機終了（10秒）をした後で再実行する。CLIは既存プロセスを強制終了しない。
書式は [DDSKKの辞書形式と送り仮名ブロック](https://ddskk.readthedocs.io/ja/latest/06_apps.html) を参照。

## 学習辞書の管理GUI

```powershell
.\out\build\windows-x64-zenz\Release\nskkzime_dictionary_gui.exe
# 別の学習辞書を操作する場合
.\out\build\windows-x64-zenz\Release\nskkzime_dictionary_gui.exe --file 'C:\検証\user-dictionary.nskkdb'
```

保存先は管理CLIと同じ。画面上部に対象ファイルを表示する。
一覧には読み・送りキー・送り・表記・注釈を表示し、絞り込みは5列の部分一致（大文字・小文字を区別）とする。
列からはみ出す内容は選択語の詳細欄で確認できる。表示する行だけをListViewへ渡し、ディスク読み込みはバックグラウンドで行う。
一覧は読み込んだ時点の保存済みデータで、他アプリの変更は「再読込」で確認する。IME内の未保存キューは表示しない。

「選択語を削除」は確認画面に示した読み・送りキー・送り・表記の組だけを削除する。
送りが空の行は共通候補であり、個別の送りとは別の行として扱う。共有辞書の候補は禁止しない。
「SKKを取り込む」はUTF-8／EUC-JPを自動判別し、検査後に候補数と新規件数を表示して確認する。
確認待ち中に元ファイルが変わっても、検査済みの内容だけを取り込む。件数は検査時点の値で、同時学習により実際の追加数は変わり得る。
不正行・未対応候補・容量超過などはCLIと同じ条件で全体を拒否する。文字コードの明示指定が必要な場合はCLIを使う。
「全件を書き出す」は絞り込みに関係なく、その時点の保存済み全件を新しいUTF-8 SKKファイルへ出す。既存ファイルは置換しない。

削除・取り込みの保存は補助プロセスへ送り、他アプリの学習と同じ経路で直列化する。
通信失敗は保存結果が不明な場合もあるため、エラー表示後は再読込してから再操作する。
保存処理中は二重操作と終了を止め、完了後に閉じられる。読み込み・取り込みの事前検査中は閉じても保存しない。
辞書が壊れている・読み込めない場合は古い一覧を消し、削除・取り込み・書き出しを無効にする。修復後に再読込できる。
単独実行ファイル、またはIMEの入力モードメニューの「学習辞書の管理…」から起動する。
メニューは初回の有効化時に取得したユーザー辞書の絶対パスを `--file` で渡す。
`NSKKZIME_USER_DICTIONARY` の一時指定も引き継ぐ。設定画面の中には管理GUIへの起動ボタンを設けていない。

2026-10-06に隔離辞書で、Unicodeと注釈の表示、送り別の削除、検査後の元ファイル変更、
注釈での絞り込み中の全件書き出し、破損時の古い一覧の消去・操作抑止を実画面で確認した。
自動テストでは共通候補と個別の送りの独立性、検査後の同時学習、同じ取り込み要求の再送、既存ファイルの保全も検証する。
DPI変更・複数ディスプレイの実測は残る。

## SKKユーザー辞書の取り込み

`--import` は通常のSKKファイルを学習用辞書へ追加する。入力は絶対パスで指定し、元ファイルを変更しない。
UTF-8／EUC-JPを自動判定する。末尾に `--encoding utf-8` または `--encoding euc-jp` を付けて明示できる。
対応する文字コード・concat・送り仮名ブロックは読み取り専用辞書と同じ。EUC-JPのSS3補助漢字も直接取り込める。

- 読み・送りキー・送り仮名が同じ組の既存候補は、順位と注釈を保つ。新しい表記を入力ファイルの順で末尾へ追加する。
- 送りを限定しない候補と、`[く/…/]` のような送り別の候補を別々に保存する。
  検索では送り別の候補を優先してから共通候補を追加し、同じ表記を重複表示しない。
- 不正な行、未対応の候補式、保存できない値が1件でもあれば全体を拒否する。候補式は実行しない。
  通常の読み取り専用辞書で行う「読める部分だけを使う」処理は、取り込みには適用しない。
- 1回50,000候補、通信データ16 MiBまで。追加後も保存先の16 MiB・50,000組・1組32候補の上限を検査する。
  上限超過で既存語や下位候補を削らず、全体をエラーにする。大規模な共有辞書は読み取り専用辞書として設定する。
- `--check-import` は元ファイルと保存先のスナップショットを検査し、追加・重複の件数を表示する。
  保存も補助プロセスの起動も行わない。件数は検査時点の値であり、保存先の書き込み権限まで保証するものではない。
- 実際の保存は補助プロセスが最新の辞書へ一括適用する。他アプリの学習を上書きせず、保存に失敗した場合は
  ディスク上の辞書とプロセス内の候補の両方を保つ。空の入力ファイルでは何も保存しない。
- 通信失敗時の再送は同じ要求IDを使う。保存後に削除された語を、古い再送で復活させない。
  CLIを改めて実行した場合は新しい取り込みなので、削除済みの語も再び追加される。

読み込み・保存・通信エラーは終了コード2。通信結果を確認できない場合は `--list` で保存状態を確認する。
書き出したSKKファイルも再取り込みできるが、世代・再送履歴・生成候補としての出自は移さず通常の辞書候補になる。

## 対応する形式

| 項目 | 現在の扱い |
|---|---|
| 文字コード | UTF-8、Windows上のEUC-JP（SS2半角カナ・SS3補助漢字を含む）。BOM、先頭行の `coding:`、内容の順で判別 |
| 改行 | LF、CRLF、末尾の改行なし |
| セクション | `;; okuri-ari entries.` / `;; okuri-nasi entries.` |
| セクションなし | ひらがなを含み末尾が英小文字の見出しを送りありと推定。それ以外は送りなし |
| 見出しと候補 | `読み /候補1;注釈/候補2/`。並び順を保持し、同じ見出しの複数行は統合 |
| 送りあり | `かk /書/描/`。検索キーは「か」＋`k` |
| 送り仮名別候補 | `おおk /大/多/[く/多/]/[き/大/]/`。一致する送りの候補を先に提示 |
| 特殊文字 | `(concat "I\057O")` など、引用文字列だけのconcat。八進エスケープ、`\\`、`\"` を解釈 |
| 括弧付きの日本語 | `(株)`・`(笑)` はそのままの表記として保持 |
| Lisp式 | 実行しない。未対応の候補式はスキップ。注釈の未対応式は文字列として保持 |
| 数値変換・動的候補 | `#` の展開、日付などの関数呼び出しは未対応 |

文字コードの自動判別ではUTF-8 BOMを最優先する。BOMがなければ先頭コメント行の
`coding: utf-8` / `utf-8-unix` / `euc-jp` / `euc-jp-unix` を使う。
指定がなければ厳密なUTF-8として読み、失敗した場合にEUC-JPを試す。
未対応のcoding指定はエラーとする。`--encoding` はcoding指定を上書きするが、BOMとの矛盾は拒否する。
通常のEUC-JPとSS2はWindowsコードページ20932を使い、バイト列の妥当性と往復変換での一致を確認する。
SS3（`8F A1..FE A1..FE`、JIS X 0212）は[Unicodeの対応表](https://www.unicode.org/Public/MAPPINGS/OBSOLETE/EASTASIA/JIS/JIS0212.TXT)の
v2.0を固定して解釈する。割当済みの6,067文字を候補・見出し・注釈で利用でき、未割当位置・途中で切れた列・
不正なバイトは辞書全体をエラーにする。表のJIS `0x2237` は `U+007E`（半角チルダ）になる。
版・チェックサム・ライセンスと再生成手順は [依存データ](../third_party/README.md) を参照。
EUC-JIS-2004は未対応で、coding指定時はエラーとする。同じSS3形でもJIS X 0213とは対応表が異なるため、
EUC-JIS-2004を `euc-jp` と指定しない。該当する辞書は対応したエディターなどでUTF-8として別名保存し、
先頭のcoding指定も `utf-8` に変更して使う。Windows以外でもUTF-8の辞書を使う。

候補内の改行・タブ・空文字列には未対応。辞書全体は128 MiB、1行は65,536コードポイントまで。
壊れた行は行単位でスキップし、未対応候補は候補単位でスキップする。
件数と先頭32件の行番号・理由を報告する。診断には見出し・候補本文を含めない。
