# nskkzime

nskkzimeは **nekomimist's skk zenz ime** の略です。SKK風の操作に、[skk-zenz](https://github.com/nekomimist/skk-zenz) の
zenzによる変換・候補採点を組み合わせる日本語IME。最初の対象はWindows / x64です。
製品のビルド・配布はzenz入りの一種類です。辞書だけの入力は推論停止時にも使える基礎機能として維持します。

現在は **最初の開発用プロトタイプ** です。OS非依存の入力コア、キー列を再生するCLI、
SKK辞書の読み込み、TSF DLLとテスト用ホストがあります。日常利用できるIMEの完成版ではありません。

## ビルド

PowerShell 7、Visual Studio 2022 Build ToolsのC++ツールセット、Windows SDK、
「C++ CMake tools for Windows」、自動テスト用のPython 3.11以上を使用します。
Pythonは標準ライブラリのみで、追加パッケージは不要です。初回に固定版llama.cppとモデルを準備します。
モデル取得の前提と手順は [zenz CPUサーバー](docs/ZENZ.md) を参照してください。

```powershell
.\scripts\prepare-zenz.ps1
.\scripts\build.ps1 -Configuration Release
```

スクリプトは `vswhere` でBuild Toolsと付属CMakeを検出し、configure・build・CTestを実行します。
デバッグ時は `-Configuration Debug`（省略時の既定）を使います。
Developer Command Promptや、CMakeをPATHに追加する操作は不要です。
子プロセスへ渡す環境変数の名前を正規化するため、`PATH` と `Path` の重複がある起動環境でも
MSBuildを実行できます。ユーザーの永続的な環境変数は変更しません。
並列ビルドは最大8ジョブを既定とし、`-Jobs 1`〜`-Jobs 64` で指定できます。
制限された実行環境でMSBuildの並列ワーカーが待機する場合は `-Jobs 1` を使います。
名前付きパイプ・共有メモリーを含むテストには、それらを利用できる通常のWindows実行環境が必要です。

出力先は `out/build/windows-x64-zenz/Debug/` または `Release/` です。
追加オプションなしで実モデル対応のCPUサーバーを含みます。従来の `-Zenz` 指定も互換用に受け付けます。
準備・変換CLI・IMEの接続設定は [zenz CPUサーバー](docs/ZENZ.md) を参照してください。
Release成果物を開発用ZIPへまとめるには [パッケージの作成と検査](docs/DISTRIBUTION.md) を参照してください。

コア・TSFの変更を短時間で確認するときだけ `-TestOnly` でllama.cppなしの構成を選べます。
出力は `out/build/windows-x64/`。これは配布対象外で、ZIP作成も拒否します。
毎回両構成をビルドする必要はなく、zenz入りReleaseのテストを製品の確認基準とします。

## 操作を試す

```powershell
.\out\build\windows-x64-zenz\Debug\skk_trace.exe 'Kanji<Space><Space><Enter>'
.\out\build\windows-x64-zenz\Debug\skk_trace.exe 'KaKu<Space><Enter>'
.\out\build\windows-x64-zenz\Debug\skk_trace.exe 'Kanji<Space>desu'
.\out\build\windows-x64-zenz\Debug\skk_trace.exe 'Kanji<Space><C-g><C-g>'
```

順に「感じ」「描く」「漢字です」、変換取消を確認できます。
CLIはUTF-8を出力します。入力はASCIIのキー列です。

辞書を指定しない場合はテスト用の5見出し（かんじ・にほん・かいとう・かk・たb）を使います。
未知語では単語登録に入り、空のままEnterで読みに戻ります。さらにEnterでかなのまま確定できます。

既存のSKK辞書も読み取り専用で利用できます。

```powershell
.\out\build\windows-x64-zenz\Release\skk_trace.exe --dict 'C:\辞書\SKK-JISYO.L' 'Jisho<Space><Enter>'
```

UTF-8／EUC-JPを判別し、候補と注釈をJSON Linesへ、読み込みの件数・診断を標準エラーへ出します。
`--dict` を繰り返すと先に指定した辞書を優先します。TSFの辞書設定は次のコマンドで保存できます。

```powershell
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --set-dictionaries 'C:\辞書\SKK-JISYO.L'
.\out\build\windows-x64-zenz\Release\nskkzime_config.exe --check
```

保存先は `%LOCALAPPDATA%\nskkzime\settings.ini`。複数の絶対パスを並べると先の辞書を優先します。
`nskkzime_settings.exe`、またはIMEの入力モードメニューの「設定…」から、同じ保存設定をGUIで編集できます。
辞書の追加・優先順、ローマ字ルール、zenzのモデル・サーバー・採点方針を指定し、保存前に検査します。
設定後は利用するアプリを起動し直します。`NSKKZIME_DICTIONARY` は一時的な上書き指定として使えます。
詳しい設定と対応形式は [辞書の利用](docs/DICTIONARIES.md) を参照してください。

## 実装済み

- ローマ字かな変換、撥音・促音・拗音、未完成ローマ字の編集。
- 外来音と `z` に続く記号入力、UTF-8ルールファイルによる追加・上書き。設定CLIとキー列CLIから利用可能。
- 最初のかな・送り仮名の途中でShiftを離すのが遅れた入力（`KAnji`、`KOroNde`、`KaKU`）を許容。
- 大文字による変換開始、送り仮名の指定、候補送り・前候補・確定・取消。
- ひらがな／カタカナ／直接英数入力、次の文字入力による候補確定。
- TSFの「あ／ア／A」入力モード項目、Windows開閉状態との同期、半角／全角・Ctrl+Space・IMEオン／オフキー。
- TSFの周辺テキスト取得（前後各40文字・入力属性の確認）と、検証アプリでの任意の文脈表示。
- ダミー変換サーバーとの非同期IPC。辞書候補のない読み・候補枯渇からの候補追加、期限・取消・古い応答の破棄。
- llama.cpp / zenz CPUサーバーの変換・採点と、設定CLIからのIME接続。モデルを別プロセスで共有し、失敗時はSKK入力を継続。
- 長い読みの生成優先、辞書候補のpromote、送り仮名付き採点。候補のキー／マウス操作後は非同期結果で順位を変えない。
- 短い追加生成語の学習を設定で有効化。長い生成候補とダミー候補は学習しない。
- `/` からのabbrev入力。英字の綴り・大小文字を保った辞書検索と、確定・取消後のかな入力への復帰。
- Windows APIに依存しないコアと辞書インターフェース。
- SKK辞書のUTF-8／EUC-JP（SS3補助漢字を含む）取り込み、注釈、送り仮名別候補、複数辞書の優先順と重複排除。
- TSFの複数辞書設定の保存、設定CLI、検証アプリでの実際の読み込み結果・エラーの表示。
- 設定GUIの5タブとバックグラウンド検査。未保存表示、読み込み時からの外部変更の検出、保存失敗時の編集内容の保持。
- 既定オフの [診断用入力ログ](docs/DIAGNOSTICS.md)。明示した保存設定と入力属性の確認後にだけ記録し、容量に上限を設けます。
- 検証アプリの [入力遅延計測](docs/INPUT_TIMING.md)。本文を収集せず、TSFキー処理と候補描画のp50/p95を表示します。
- 辞書本体の初回読み込みを非同期化。同一プロセスでは読み込みを共有し、待機中もかな入力・確定・取消を継続。
- 読み取り専用辞書の永続キャッシュとアプリ間の共有メモリー。変更・破損を検出し、利用できない場合は通常読み込みに復帰。
- 確定候補の学習とユーザー辞書への保存。補助プロセスに書き込みを集約し、他アプリと非同期に同期。
- 未知語・候補枯渇時の単語登録。別欄でSKK入力し、送り仮名・abbrev・再帰登録・取消に対応。
- 保存した語の一覧、送り仮名別の削除、UTF-8 SKK形式への書き出しと、SKKファイルの事前検査・一括取り込みを行う辞書管理CLI。
- 学習辞書の管理GUI。読み・送り・表記・注釈の絞り込み、確認付きの選択語削除・取り込み、新規ファイルへの全件書き出し。
- 入力モードメニューから「設定…」「学習辞書の管理…」を別プロセスで起動。IMEが使う設定・学習辞書の保存先を引き継ぎます。
- 候補選択中の `X` → `yes`＋Enterによる学習語の削除。送り別／共通候補を区別し、取消・編集失敗・入力欄移動では保存しません。
- TSF編集失敗・取消・パスワード／private属性・属性不明の入力欄では学習しない処理と、学習の有効／無効設定。
- TSFのCOM生成・初期化・終了、キー通知、編集セッション、composition。
- 失敗した同期編集でキーを奪わない処理と、フォーカス移動時の旧入力欄の後処理。
- 選択範囲・アプリ側の変更の監視、上書き前の内容照合、読み／候補のTSF下線表示。
- キャレット付近の候補一覧・注釈・7件単位の表示。Space／xとPageDown／PageUpに追従し、確定・取消・フォーカス移動で閉じます。
- 表示ページの `1`〜`7` による候補の直接選択。登録欄内では選んだ語を欄へ追加して入力を続けます。
- フォーカスを保った候補行のクリック選択。登録欄内でも利用でき、処理待ちの間に入力が変わったクリックは破棄します。
- TSFのUIElement通知と、入力アプリが独自の候補UIを表示する場合の抑制。
- 開発用登録・解除エクスポート。ビルドとテストは登録を実行しません。
