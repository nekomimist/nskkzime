# nskkzime

SKK風の操作に、[skk-zenz](https://github.com/nekomimist/skk-zenz) の
zenzによる変換・候補採点を組み合わせる日本語IME。最初の対象はWindows / x64です。

現在は **最初の開発用プロトタイプ** です。OS非依存の入力コア、キー列を再生するCLI、
SKK辞書の読み込み、TSF DLLとテスト用ホストがあります。日常利用できるIMEの完成版ではありません。

## ビルド

PowerShell 7、Visual Studio 2022 Build ToolsのC++ツールセット、Windows SDK、
「C++ CMake tools for Windows」を使用します。通常ビルドは外部ライブラリのダウンロード不要です。

```powershell
.\scripts\build.ps1
.\scripts\build.ps1 -Configuration Release
```

スクリプトは `vswhere` でBuild Toolsと付属CMakeを検出し、configure・build・CTestを実行します。
Developer Command Promptや、CMakeをPATHに追加する操作は不要です。
子プロセスへ渡す環境変数の名前を正規化するため、`PATH` と `Path` の重複がある起動環境でも
MSBuildを実行できます。ユーザーの永続的な環境変数は変更しません。

出力先は `out/build/windows-x64/Debug/` または `Release/` です。
実モデル入りのCPUサーバーは `.\scripts\prepare-zenz.ps1` で固定版の依存とモデルを取得し、
`.\scripts\build.ps1 -Configuration Release -Zenz` で別ディレクトリーへビルドします。
準備・変換CLI・IMEの接続設定は [zenz CPUサーバー](docs/ZENZ.md) を参照してください。

| ファイル | 用途 |

| `nkkz-ime-server.exe` | 通常版はダミー、`-Zenz` 版は実モデルの変換・採点。パイプ／標準入出力 |
| `nskkzime_user_dictionary.exe` | 登録・学習語の一覧、削除、SKKファイルの書き出し・一括取り込み |
| `nskkzime_tsf.dll` | 開発用のTSF Text Input Processor |
| `tsf_smoke.exe` | DLLのCOMインターフェースとTSFアダプターの契約テスト |

## 操作を試す

```powershell
.\out\build\windows-x64\Debug\skk_trace.exe 'Kanji<Space><Space><Enter>'
.\out\build\windows-x64\Debug\skk_trace.exe 'KaKu<Space><Enter>'
.\out\build\windows-x64\Debug\skk_trace.exe 'Kanji<Space>desu'
.\out\build\windows-x64\Debug\skk_trace.exe 'Kanji<Space><C-g><C-g>'
```

順に「感じ」「描く」「漢字です」、変換取消を確認できます。
CLIはUTF-8を出力します。入力はASCIIのキー列です。

辞書を指定しない場合はテスト用の5見出し（かんじ・にほん・かいとう・かk・たb）を使います。
未知語では単語登録に入り、空のままEnterで読みに戻ります。さらにEnterでかなのまま確定できます。

既存のSKK辞書も読み取り専用で利用できます。

```powershell
.\out\build\windows-x64\Release\skk_trace.exe --dict 'C:\辞書\SKK-JISYO.L' 'Jisho<Space><Enter>'
```

UTF-8／EUC-JPを判別し、候補と注釈をJSON Linesへ、読み込みの件数・診断を標準エラーへ出します。
`--dict` を繰り返すと先に指定した辞書を優先します。TSFの辞書設定は次のコマンドで保存できます。

```powershell
.\out\build\windows-x64\Release\nskkzime_config.exe --set-dictionaries 'C:\辞書\SKK-JISYO.L'
.\out\build\windows-x64\Release\nskkzime_config.exe --check
```

保存先は `%LOCALAPPDATA%\nskkzime\settings.ini`。複数の絶対パスを並べると先の辞書を優先します。
設定後は利用するアプリを起動し直します。`NSKKZIME_DICTIONARY` は一時的な上書き指定として使えます。
詳しい設定と対応形式は [辞書の利用](docs/DICTIONARIES.md) を参照してください。

## 実装済み

- ローマ字かな変換、撥音・促音・拗音、未完成ローマ字の編集。
- 外来音と `z` に続く記号入力、UTF-8ルールファイルによる追加・上書き。設定CLIとキー列CLIから利用可能。
- 最初のかな・送り仮名の途中でShiftを離すのが遅れた入力（`KAnji`、`KOroNde`、`KaKU`）を許容。
- 大文字による変換開始、送り仮名の指定、候補送り・前候補・確定・取消。
- ひらがな／カタカナ／直接英数入力、次の文字入力による候補確定。
- TSFの「あ／ア／A」入力モード項目、Windows開閉状態との同期、半角／全角・Ctrl+Space・IMEオン／オフキー。
- TSFの周辺テキスト取得（前後各40文字・入力属性の確認）と、検証アプリでの任意の文脈表示。
- ダミー変換サーバーとの非同期IPC。辞書候補のない読み・候補枯渇からの候補追加、期限・取消・古い応答の破棄。
- llama.cpp / zenz CPUサーバーの変換・採点と、設定CLIからのIME接続。モデルを別プロセスで共有し、失敗時はSKK入力を継続。
- 長い読みの生成優先、辞書候補のpromote、送り仮名付き採点。候補のキー／マウス操作後は非同期結果で順位を変えない。
- 短い追加生成語の学習を設定で有効化。長い生成候補とダミー候補は学習しない。
- `/` からのabbrev入力。英字の綴り・大小文字を保った辞書検索と、確定・取消後のかな入力への復帰。
- Windows APIに依存しないコアと辞書インターフェース。
- SKK辞書のUTF-8／EUC-JP（SS3補助漢字を含む）取り込み、注釈、送り仮名別候補、複数辞書の優先順と重複排除。
- TSFの複数辞書設定の保存、設定CLI、検証アプリでの実際の読み込み結果・エラーの表示。
- 確定候補の学習とユーザー辞書への保存。補助プロセスに書き込みを集約し、他アプリと非同期に同期。
- 未知語・候補枯渇時の単語登録。別欄でSKK入力し、送り仮名・abbrev・再帰登録・取消に対応。
- 保存した語の一覧、送り仮名別の削除、UTF-8 SKK形式への書き出しと、SKKファイルの事前検査・一括取り込みを行う辞書管理CLI。
- TSF編集失敗・取消・パスワード／private属性・属性不明の入力欄では学習しない処理と、学習の有効／無効設定。
- TSFのCOM生成・初期化・終了、キー通知、編集セッション、composition。
- 失敗した同期編集でキーを奪わない処理と、フォーカス移動時の旧入力欄の後処理。
- 選択範囲・アプリ側の変更の監視、上書き前の内容照合、読み／候補のTSF下線表示。
- キャレット付近の候補一覧・注釈・7件単位の表示。Space／xとPageDown／PageUpに追従し、確定・取消・フォーカス移動で閉じます。
- 表示ページの `1`〜`7` による候補の直接選択。登録欄内では選んだ語を欄へ追加して入力を続けます。
- フォーカスを保った候補行のクリック選択。登録欄内でも利用でき、処理待ちの間に入力が変わったクリックは破棄します。
- TSFのUIElement通知と、入力アプリが独自の候補UIを表示する場合の抑制。
- 開発用登録・解除エクスポート。ビルドとテストは登録を実行しません。

## 検証の範囲

2026-10-06、MSVC 19.44 / Windows SDK 10.0.26100.0で検証しています。
Debug／ReleaseのCTest各28件がすべて成功しています。
実モデル入りRelease版は33件。移植元のprompt/modelテストと、実モデルの並行IPC・取消・CLI・DLL経由の自動起動と変換・候補採点も確認しています。
`core` は62ケース（固定シードによる10,000イベントの状態検査を含む）です。
`romaji` は14ケースで、外来音・記号・独自ルール・持ち越し・不正設定・登録欄・送り仮名・Shiftと10,000キーの入力を検証します。
`romaji_trace` はルールファイルを指定したCLI入力、`tsf_romaji` は保存設定のDLL接続・カタカナ・編集失敗・ルールの保持と読み込み失敗時の復帰を検証します。
`registration` は15ケース（別の10,000イベントの状態検査を含む）で、登録の再帰・制限・取消・即時再利用を検証します。
`dictionary` は33ケースで、形式・文字コード・送り仮名・辞書間の候補統合と、SS3の全6,067文字を検証します。
`settings` は20ケースで、設定形式・学習／ローマ字／推論設定・保存失敗時の保全・複数辞書の部分的な読み込み失敗を検証します。
`learning` は10ケースで、永続化・送り別の順位・再送の重複排除・複数プロセス・保存失敗・強制終了後の復旧・削除の同期・一括取り込みと並行学習を検証します。
`user_dictionary` は12ケースで、削除範囲・削除後の再登録・SKK書き出し／取り込みの順位・文字・送り範囲の保持・容量超過時の保全を検証します。
`user_dictionary_cli` は管理CLIの一連の操作、Unicode、UTF-8／EUC-JP取り込み、事前検査、既存ファイルの保全を隔離した保存先で確認します。
`tsf_learning` は本文の編集成功時だけの学習、保護された入力欄と属性取得失敗の除外、次の変換への反映を検証します。
自動テストは隔離したファイルを使い、ユーザーの学習データには書き込みません。
`config_cli` で設定コマンド、`tsf_settings` / `tsf_invalid_settings` で保存設定のTSF接続を検証します。
`tsf_smoke` はCOM生成・参照寿命、実TSFマネージャーの起動、テスト用ホスト上での
入力・候補確定・取消・失敗時の復旧・遅延した後処理と新入力欄の分離を検証します。
辞書を指定したTSF入力、辞書読み込み失敗時のかな入力、CLIの辞書読み込みもCTestで確認します。
選択変更・貼り付け・外部編集・空のabbrev・同一入力欄での遅延終了との競合を16シナリオで検証し、
表示属性のCOMインターフェースも検査します。
`tsf_local_activation` はCOMマニフェストによるビルド先DLLの読み込みを検証します。
`candidate_ui` は送り仮名付き候補・ページ境界・ホスト指定のページ・COM契約を検査します。
`tsf_candidate_click` はクリックの非同期編集、連打の集約、取消・追加入力・別欄移動・外部編集後の破棄、
失敗時の再試行、登録欄への追加、入力属性の学習制限、保存とオブジェクト寿命を検査します。
`input_mode` はTSFのモード表示・開閉同期・メニュー・キー切替、未確定入力の終了と登録の破棄、解除後の通知停止を検査します。
`context_text` は変換範囲の除外、前後40文字、UTF-16、保護・不明属性、取得失敗、編集後の更新と取消・解除時の文脈破棄を検査します。
`inference` はJSONの検証、コアへの候補追加、実パイプの並行接続・取消・期限・再起動を検査します。
`inference_policy` は11ケースで長い読み・promote・候補操作後の保全・重複除去・送り仮名・生成語の学習方針を検査します。
`tsf_inference_policy` は遅延する実パイプで順位変更の取消、マウス押下、期限切れ、編集失敗、送り仮名の文脈と学習の永続化を検査します。
`tsf_inference` は実サーバーからの候補反映、追加入力・取消・別欄・文脈変更・書き込み失敗・保護属性・
解除後の応答破棄、編集待ち中の期限切れ、通常登録への復帰、ダミー候補を学習しないことを検査します。
TSF側ではUIの開始・更新・終了、表示抑制、UI失敗時の変換継続、古いレイアウト通知も検証します。

**登録したIMEで標準EDIT／RichEditのかな入力・候補送り・確定・取消を確認しました。**
TSFを有効にしたRichEditでは、ビルド版DLLで矢印移動後の入力も確認しています。
標準EDITの互換入力経路では最初の矢印が確定だけになる制限が残ります。
テスト用ホストはWindowsのテキストストアやキー配送の完全な再現ではありません。
登録解除・更新後のDLLハッシュと実入力を確認しました。
2026-10-05には、ビルド版の候補一覧・注釈・選択行の追従と確定時の終了をRichEditで確認しています。
abbrevの英字入力・確定後のかなへの復帰も標準EDIT／RichEditで確認しました。
保存した外部辞書を環境変数なしで読み込み、RichEditの「辞書」と標準EDITのabbrev「SKK」を確定できました。
候補学習ではRichEditで選んだ「掛く」の保存と、別プロセスで起動した標準EDITへの第一候補としての反映を確認しました。
隔離版の検証アプリでは、単語登録内の変換・再帰登録・取消・送りあり登録と、再起動後の登録語の利用を確認しました。
16候補の専用fixtureを使い、標準EDIT／RichEditのPageDown／PageUpと候補一覧の3ページ表示も確認しています。
数字キーによる直接選択も両入力欄で確認し、RichEditでは登録欄への候補追加・継続入力・保存まで確認しました。
入力モードの表示・Ctrl+Space／C-jによる切替・切替後の連続入力を両入力欄で確認しました。
システムトレイの実表示は登録版更新後の検証が残ります。
文脈確認をオンにした隔離版では、RichEditで前後の日本語と絵文字を取得し、変換対象を含まないことを確認しました。
標準EDITの互換入力経路からは前後とも空文字列が返りました。この経路は文脈なしで扱います。
ダミー推論の候補表示・確定も両入力欄で確認し、RichEditでは待機中の取消と別欄移動後に応答が混入しないことを確認しました。
候補のクリック選択と確定後の継続入力も両入力欄で確認し、RichEditではドラッグの取消・登録欄への追加と保存を確認しました。
実画面で見つかった操作案内の欠けは、候補ウィンドウの寸法に枠の幅を加えて修正しました。
入力属性を提供しないアプリでは学習を見送ります。検証アプリは通常のテキスト欄であることを明示しています。
ブラウザ等の互換性は引き続き検証します。

推論は既定で無効です。実モデルへの接続は保存設定から、隔離したプローブは `.\scripts\probe-zenz.ps1` から利用できます。
実モデルのDLL接続は自動テストで確認済みですが、実アプリでの画面操作は未確認です。
利用方法と制約は [推論IPCの検証](docs/INFERENCE.md) と [zenz CPUサーバー](docs/ZENZ.md) を参照してください。
IME内の登録語削除、GUI設定画面、外部アプリでの互換性検証は引き続き進めます。
